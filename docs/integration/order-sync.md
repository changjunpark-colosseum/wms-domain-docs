# 주문 연동

<div class="page-meta"><span>연동</span><span>주문</span><span>12분</span></div>

주문 연동은 외부 채널의 주문을 CGKR 출고 주문으로 생성하고, 이후 변경·취소와 출고·송장 결과를 다시 외부 채널에 전달하는 왕복 과정이다.

## 한눈에 보기

```text
1. 외부 상품 등록
2. 외부 주문 등록
3. ITF 연동 대기
4. 상품 등록·매핑
5. CGKR 출고 주문 생성
6. 주문 변경·취소 반영
7. 피킹·패킹·송장·출고 완료
8. 외부 채널에 결과 전달
```

## 1. 채널 연결정보

외부 요청은 연동 인증정보를 통해 다음 연결정보로 변환된다.

- 화주사
- 센터
- 쇼핑몰 유형
- 쇼핑몰 연결 ID
- 상품·주문·재고·출고결과 연동 사용 여부

인증정보 자체를 상품·주문에 복제하지 않고, 확인된 쇼핑몰 연결 ID와 화주·센터를 수집 데이터에 저장한다.

## 2. 상품 선행 등록

주문 상품을 내부 SKU와 연결하려면 외부 상품이 먼저 수집돼 있어야 한다.

```text
POST /api/v1/oms/product
→ 외부 상품번호 중복 확인
→ SKU·바코드·UOM·관리속성 저장
→ itf_item_collect_info
→ sync_item_stats_cd = WAIT
```

상품은 `쇼핑몰 연결 ID + 외부 상품번호`로 식별한다. 이미 같은 외부 상품이 있으면 중복 등록을 거절하고, 수정은 기존 수집 행과 변경 이력에 반영한다.

## 3. 주문 수집

외부 채널·COLO 연동 서비스가 주문을 Push API로 전달한다.

```text
POST /api/v1/oms/order
→ 연동 인증·화주·센터 확인
→ 외부 주문번호 중복 확인
→ 주문자·수취인·주소·배송 조건 저장
→ 각 주문 상품의 외부 상품번호 조회
→ 주문 마스터·상품 상세·이력 저장
→ sync_stats_cd = WAIT
```

주문은 `쇼핑몰 연결 ID + 외부 주문번호`로 중복을 막는다. 주문 상품은 같은 쇼핑몰 연결의 외부 상품번호와 연결하며, 선행 상품이 없으면 주문 저장을 거절한다.

## 4. ITF 수집 모델

| 데이터 | 주요 내용 |
|---|---|
| 상품 수집 | 외부 상품번호, SKU, 바코드, UOM, 화주·센터, 동기화 상태 |
| 주문 수집 | 외부 주문번호, 주문·결제·수집 시각, 수취인·주소, 배송 조건 |
| 주문 상품 | 외부 상품 연결, 라인 ID, 수량, LOT·유효기간, 가격 |
| 수집 이력 | 등록·수정 시점의 주문과 상품 스냅샷 |

외부 주문 원본과 실제 CGKR 출고 주문은 같은 객체가 아니다. 수집 주문에 CGKR 출고 ID를 연결해 양쪽 상태를 추적한다.

## 5. CGKR 주문 생성

`cgkr_batch`는 쇼핑몰 API를 직접 호출하지 않는다. ITF 테이블의 연동 대기 데이터를 1분 간격으로 조회해 CGKR에 전달한다.

```text
OutboundOrderTask
├─ 상품 등록·매핑
├─ 신규 출고 주문 생성
└─ 주문 변경·취소 반영
```

### 상품 매핑

`sync_item_stats_cd = WAIT`인 상품을 조회해 CGKR 상품 등록·매핑 API로 보낸다.

### 신규 주문

다음 조건을 만족하는 수집 주문을 대상으로 한다.

- `sync_stats_cd = WAIT`
- 삭제되지 않은 주문·상품
- 주문수량이 0보다 큼
- 외부 상품 수집 정보가 존재함
- 사용 가능한 센터가 연결됨

대상별로 내부 동기화 API를 호출한다.

```text
POST /api/v1/itf/sync-outbound
```

상품·신규 주문·변경 주문은 각각 최대 20개 작업을 병렬 실행한다.

## 6. 변경·취소

```text
PUT /api/v1/oms/order/{orderNo}
PUT /api/v1/oms/order/cancel/{orderNo}
```

| 외부 상태 | 코드 | 의미 |
|---|---|---|
| 일반 | GEN | 신규·정상 주문 |
| 변경 | MOD | 상품·수량·주소 등 주문 수정 |
| 취소 | CNL | 외부 주문 취소 |
| 처리 완료 | FFLD | 외부 fulfillment 완료 |

변경·취소는 CGKR 출고가 아직 작업 가능한 대기 상태이고 외부 수정 시각이 CGKR 반영 시각보다 최신인 경우에 동기화한다.

```text
POST /api/v1/itf/sync-change-outbound
```

이미 피킹·패킹·출고가 진행된 주문은 단순 수정이 아니라 단계별 취소·예외 정책을 따라야 한다.

## 7. 동기화 상태

| 상태 | 의미 |
|---|---|
| WAIT | CGKR 연동 대기 |
| DONE | CGKR 연동 완료 |
| STOP | 연동 제한 |
| UNSC | 연동 비활성 |
| PEND | 확인·재처리 대기 |

수집 상태와 CGKR 출고 업무 상태를 같은 필드로 사용하지 않는다. `WAIT` 수집 주문이 CGKR에 생성된 뒤에는 생성된 출고번호와 동기화 완료 상태를 함께 확인해야 한다.

## 8. 출고 결과 회신

CGKR에서 출고·송장 사건이 발생하면 `cgkr_oms`가 외부 전달 큐를 만든다.

```text
CGKR 출고 완료·송장 사건
→ 웹훅 큐 등록
├─ 대표 송장·출고 완료
├─ 추가 송장
└─ 송장 취소
→ 채널별 fulfillment API·웹훅 호출
→ 성공·실패 상태 저장
```

출고 결과 동기화도 1분 간격으로 실행된다. 외부 전달 실패 때문에 CGKR의 출고 완료나 재고 차감을 다시 실행하지 않는다.

## 중복 방지 기준

| 대상 | 중복 식별 기준 |
|---|---|
| 상품 | 쇼핑몰 연결 ID + 외부 상품번호 |
| 주문 | 쇼핑몰 연결 ID + 외부 주문번호 |
| 주문 상품 | 수집 주문 + 외부 상품 + 주문 라인 ID |
| 출고 결과 | CGKR 출고 + 웹훅 이벤트 유형 |

## 실패와 재처리

1. 상품 미등록 주문은 저장 단계에서 차단한다.
2. CGKR 동기화 실패는 성공으로 변경하지 않고 실패 사유를 남긴다.
3. 연동 대기 상태가 유지되면 다음 배치에서 다시 처리될 수 있다.
4. 현재 `cgkr_batch`에는 행별 지수 백오프·최대 재시도·Dead Letter 정책이 명확히 보이지 않는다.
5. 반복 실패는 상품 매핑, 화주·센터 연결, 배송 프로필과 주문 payload를 확인한다.
6. 재전송 시 외부 식별자를 유지해 중복 상품·출고 주문 생성을 차단한다.

## 장애 확인 순서

| 증상 | 확인 순서 |
|---|---|
| 주문 API가 실패함 | 채널 인증 → 화주·센터 → 외부 상품 선행 등록 → 중복 주문번호 |
| ITF에는 있지만 CGKR에 없음 | 상품 매핑 상태 → 주문 WAIT 상태 → 배치 실행 이력 → sync-outbound 응답 |
| 변경·취소가 반영되지 않음 | 외부 수정 시각 → CGKR 출고 단계 → MOD·CNL 상태 → 변경 배치 |
| CGKR 출고 완료가 외부에 없음 | fulfillment 큐 → 웹훅 대상 → 채널 응답 → 재처리 상태 |
