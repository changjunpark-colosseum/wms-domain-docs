# 핵심 불변식

<div class="page-meta"><span>부록</span><span>검증 기준</span><span>10분</span></div>

불변식은 정상 흐름뿐 아니라 취소·재시도·부분 처리·동시 작업에서도 항상 지켜져야 하는 규칙입니다.

## 1. 수량 보존

```text
이동 전 총량 = 이동 후 출발지 잔량 + 도착지 수량
분할 전 수량 = 부모 잔량 + 모든 자식 수량
SOH = Available + Allocated + WIP + Unavailable
```

## 2. 멱등성

같은 업무 요청을 여러 번 처리해도 최종 결과는 한 번 처리한 것과 같아야 합니다.

대표 대상:

- 입고확정과 출고확정
- 재고 조정·폐기
- 송장 발번 요청
- 외부 재고·정산 이벤트 수집

## 3. 원자성

하나의 업무 사실을 구성하는 변경은 전부 성공하거나 전부 실패해야 합니다.

- 출발지 감소와 도착지 증가
- Available 감소와 Allocated 증가
- 박스 완료와 내용물 연결
- 폐기확정과 SOH 감소

## 4. 추적 가능성

모든 수량·상태 변화에서 다음 질문에 답할 수 있어야 합니다.

- 어떤 업무 사건이 바꿨는가?
- 누가 언제 처리했는가?
- 이전 값과 이후 값은 무엇인가?
- 어떤 주문·작업·LPN·Location과 연결되는가?
- 취소나 정정이 있다면 어떤 원본을 반대로 처리했는가?

## 5. 상태 전이의 단조성

완료된 상태를 임의로 이전 상태로 덮어쓰지 않습니다. 취소·반품·정정은 별도 사건으로 표현하고 이력을 보존합니다.

## 6. 격리

정상 출고 자격이 없는 재고는 Available과 구분합니다.

- 입고확정 후 미적치
- 품질 HOLD·불량
- 반품 검수 전 재고
- 폐기 후보
- 실사·이동 작업 중 재고

## 7. 시스템 간 대사

외부 시스템 전송 성공만으로 업무 완료를 단정하지 않습니다. 양쪽의 식별자·수량·상태를 비교하고 차이를 재처리할 수 있어야 합니다.

## 테스트에 적용하기

| 시나리오 | 함께 확인할 것 |
|---|---|
| 정상 입고 | SOH 증가 1회, 미적치 상태, 수불 이력 |
| 부분 이동 | 출발지+도착지 총량, LPN 계보, 잔량 |
| 출고 취소 | 할당 해제, WIP putback, 송장 무효화 |
| 중복 요청 | 두 번째 요청의 무효 처리, 최종 수량 동일 |
| 네트워크 오류 | 서버 처리 여부 재조회, 중복 이벤트 방지 |
| 동시 작업 | 잠금 충돌, 초과 피킹·음수 재고 방지 |

::: tip QA 관점
화면의 성공 메시지만 확인하지 말고 `객체 상태`, `수량`, `Location`, `이력`, `외부 결과`를 함께 검증하세요.
:::

## 확인 문제

1. 멱등성과 중복 요청 거절은 언제 같은 결과이고 언제 다를까요?
2. 완료 상태를 이전 상태로 되돌리는 대신 반대 이벤트를 쓰는 이유는 무엇일까요?
3. 재고 수량은 맞지만 수불 이력이 없다면 어떤 운영 문제가 생길까요?
