# COLO 1.0

<div class="page-meta"><span>기타</span><span>시스템 연동</span><span>10분</span></div>

COLO 1.0은 화주가 상품·주문·배송·쇼핑몰 연동과 정산 업무를 처리하는 운영 시스템이다. CGKR이 센터의 입고·재고·출고·반품 작업을 실행하는 WMS라면, COLO 1.0은 화주와 외부 판매 채널의 요청을 물류 작업으로 연결하는 OMS·운영 포털에 가깝다.

## 시스템 역할

| COLO 1.0 | CGKR |
|---|---|
| 화주·쇼핑몰 관점의 상품 관리 | 센터 작업에 필요한 상품 기준정보 사용 |
| 출고 요청·주문 관리 | 재고 할당·피킹·패킹·상차 |
| 배송현황 조회 | 송장·실제 출고 결과 생성 |
| 반품 요청 | 반입·검수·양품화·폐기 |
| 청구명세서·정산 | 물류 사용량과 작업 결과 제공 |

한 기능이 CGKR 메뉴 안에서 보이더라도 실제 화면과 데이터의 소유자가 COLO 1.0일 수 있다.

## 전체 연결

```text
외부 쇼핑몰·화주
       ↓
    COLO 1.0
상품·출고요청·반품요청·정산
       ↕
      CGKR
입고·재고·피킹·패킹·송장·반품 작업
       ↓
센터 실물 작업·택배사
```

## CGKR에서 연결되는 기능

| 기능 | 연결 방식 | 역할 |
|---|---|---|
| 상품 관리 | COLO 화면을 CGKR 안에서 제공 | 상품 등록·수정 |
| 출고 신청 | COLO 출고 요청 화면 연결 | 화주의 B2C 출고 요청 |
| 배송현황 | COLO 배송현황 화면 연결 | 주문·송장·배송상태 조회 |
| 쇼핑몰 연동 | COLO 쇼핑몰 연동 화면 연결 | 판매 채널 계정·연동 관리 |
| 반품 신청 | COLO 반품 신청 화면으로 이동 | 화주 반품 요청 등록 |
| 정산관리 | COLO 청구명세서 화면 연결 | 물류비 명세·결제 상태 조회 |

## 화면 연결과 데이터 연동

COLO 화면을 CGKR 안에 iframe으로 표시하는 것은 화면 이동과 인증 문맥을 연결하는 방식이다. 상품·주문·정산 데이터가 CGKR 데이터베이스로 복제됐다는 의미는 아니다.

```text
화면 연결
CGKR 메뉴 → COLO 화면 표시

데이터 연동
COLO 사건 → API·배치·메시지 → CGKR 데이터 반영
```

두 방식을 구분해야 장애가 발생했을 때 어느 시스템의 화면·API·데이터를 확인할지 판단할 수 있다.

## 상품

일반 Product·SKU 등록은 COLO 1.0에서 시작하고 CGKR은 전달받은 상품정보를 입고·재고·출고 기준으로 사용한다.

```text
COLO 상품 저장
→ CGKR 상품정보 전달
├─ 성공: 센터 업무에서 사용
└─ 실패: 실패 사유 확인 → 최신 상품정보 재전송
```

상품 재전송은 과거 요청값이 아니라 현재 저장된 최신 상품정보를 기준으로 해야 한다. 상품 동기화가 실패하면 해당 SKU를 사용하는 입고·출고가 잘못된 상품을 참조하지 않도록 확인한다.

## 출고·배송

COLO 1.0에서 작성한 출고 요청은 CGKR의 출고 주문과 작업으로 연결된다. CGKR이 피킹·패킹·송장·출고를 완료하면 송장번호와 실제 발송 결과를 화주가 조회할 수 있어야 한다.

```text
COLO 출고 요청
→ CGKR 출고 주문
→ 피킹·패킹
→ 송장·출고 완료
→ COLO 배송현황
```

출고 요청과 CGKR 출고번호를 연결하고, 같은 요청이 재전송돼도 출고 주문을 중복 생성하지 않는다.

## 반품

화주는 COLO 1.0에서 반품을 요청할 수 있고, 센터는 CGKR에서 원출고·송장을 기준으로 반입·검수·품질 판정과 재입고·폐기를 처리한다.

반품 요청 상태와 센터 실물 처리 상태는 같은 값이 아니다. COLO의 요청 완료가 CGKR의 양품화·폐기 완료를 대신하지 않는다.

## 정산

CGKR의 정산 메뉴는 COLO 1.0 청구명세서 화면을 제공한다. 물류비 계산·명세서 생성·발행·결제·마감의 주된 책임은 COLO 1.0에 있다.

정산은 CGKR의 다음 결과를 사용한다.

- 입고·출고·반품 작업량
- 택배·송장 건수
- 사용한 Box·부자재
- 일별 보관 수량
- 추가 작업·관리자 조정

CGKR에서 COLO 명세서를 볼 수 있다는 이유로 CGKR이 정산 금액을 계산한다고 해석하지 않는다.

## 연동 정책

1. 화주·상품·주문·송장·반품의 시스템 간 식별키를 보존한다.
2. 화면 연결과 데이터 동기화를 구분한다.
3. 같은 요청을 재처리해도 상품·주문·재고를 중복 생성하지 않는다.
4. 전송 성공·실패와 실패 사유를 기록한다.
5. 실패 건은 현재 정본의 최신값으로 재전송할 수 있어야 한다.
6. 오래된 이벤트가 최신 상품·주문 상태를 덮어쓰지 않게 한다.
7. CGKR 작업 결과 전송 실패가 재고 증감 작업을 다시 실행하지 않게 한다.
8. 사용자가 접근 가능한 화주·센터 범위를 두 시스템에서 일치시킨다.
9. COLO 연동 메뉴를 숨기는 기능과 실제 데이터 연동 중단을 같은 것으로 간주하지 않는다.

## 장애 확인 순서

| 증상 | 먼저 확인할 곳 |
|---|---|
| CGKR 안에서 COLO 화면이 열리지 않음 | 로그인 문맥·화면 URL·iframe 연결 |
| COLO 상품이 CGKR에 없음 | 상품 전송 결과·매핑키·재전송 |
| 출고 요청이 CGKR에 없음 | 주문 연동 결과·중복키·센터 매핑 |
| 송장은 발행됐지만 배송현황에 없음 | CGKR 출고 결과 전송·COLO 반영 상태 |
| 정산 금액이 다름 | 원본 작업량·송장·박스·보관량과 COLO 요율·조정 |
