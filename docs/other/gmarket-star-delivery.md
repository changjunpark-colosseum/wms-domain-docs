# G마켓 스타배송

<div class="page-meta"><span>기타</span><span>G마켓</span><span>10분</span></div>

스타배송은 상품 보관·포장·택배 업무를 연결하고 구매자에게 도착 예정일을 보장하는 G마켓의 물류 서비스다. WMS에서는 스타배송 주문을 일반 B2C 주문과 구분하고 약속한 발송 마감일과 택배 서비스 등급을 지켜 출고해야 한다.

## 서비스 구분

| 구분 | 재고를 보관하는 곳 | 출고 운영 |
|---|---|---|
| 풀필먼트 스타배송 | 스타배송 물류센터 | 센터가 입고·재고·피킹·패킹·배송을 처리 |
| 판매자 스타배송 | 판매자 창고 | 판매자가 출고하고 계약된 택배사의 도착보장 서비스를 사용 |

풀필먼트 스타배송에는 상온·저온·셀러플렉스·멀티채널 등 운영 방식이 있다. 어떤 방식을 사용하더라도 WMS는 주문이 요구하는 배송 유형과 마감 정보를 작업이 끝날 때까지 보존해야 한다.

## 전체 흐름

<div class="flow-strip"><span>G마켓 주문 수집</span><i>→</i><span>스타배송 식별</span><i>→</i><span>발송 마감일 확인</span><i>→</i><span>피킹·패킹</span><i>→</i><span>도착보장 송장 출력</span><i>→</i><span>상차·출고 완료</span></div>

```text
스타배송 상품·주문
→ shippingType으로 일반 배송과 구분
→ shippingDueAt 기준으로 작업 우선순위 확인
→ 일반 출고와 동일하게 재고 할당·피킹·패킹
→ 택배사·서비스 등급에 맞는 송장 발번·출력
→ 송장·실제 발송 결과 연결
```

## 출고 조회

스타배송 기능이 활성화된 출고 목록에서는 다음 조건을 사용한다.

| 항목 | 역할 |
|---|---|
| 배송 방식 | 전체·일반배송·스타배송 주문을 구분해 조회 |
| 주문수집일 | WMS에 주문이 들어온 시점을 기준으로 조회 |
| 발송 마감일 | 약속된 출고 처리 기한을 기준으로 조회 |
| 발송 마감일시 | 개별 주문이 센터에서 출고돼야 하는 시각 |
| 택배 서비스 등급 | 일반·도착보장 송장 양식을 결정하는 정보 |

배송 방식 필터는 주문 기준 조회에서 사용한다. 기능이 비활성화돼 있을 때는 배송 방식 조건을 서버에 보내지 않고 주문수집일 기준으로 조회한다.

## 발송 마감일

스타배송 작업의 우선순위는 단순 주문 접수 순서만으로 결정하지 않는다. `발송 마감일시`를 함께 확인해 마감이 임박한 주문이 피킹·패킹 대기열에서 누락되지 않게 한다.

### 정책

1. 스타배송 여부를 쇼핑몰 이름만으로 판단하지 않고 배송 방식 필드를 사용한다.
2. 주문수집일과 발송 마감일을 서로 다른 날짜 기준으로 관리한다.
3. 작업 생성·피킹·패킹·상차에서도 원주문의 발송 마감일을 유지한다.
4. 마감일이 없거나 이미 지난 주문은 일반 정상 건과 분리해 확인한다.
5. 스타배송과 일반배송이 한 작업에 섞이면 상품 수량뿐 아니라 서비스 등급과 마감 조건도 구분할 수 있어야 한다.

## 송장

CGKR의 CJ 송장 출력은 택배 서비스 등급에 따라 출력 양식을 선택한다.

| 택배사 | 서비스 등급 | 출력 양식 |
|---|---|---|
| CJ | `GUARANTEED` | CJ ONE 스타배송 송장 |
| CJ | 일반·누락·알 수 없음 | CJ 일반 송장 |

```text
송장 출력 결과 수신
→ 택배사 CJ 확인
→ 서비스 등급 GUARANTEED 확인
→ CJ ONE ZPL 생성
→ 프린터 전송
```

### 정책

1. 스타배송 주문이라는 이유만으로 송장 양식을 추정하지 않고 송장 결과의 서비스 등급을 확인한다.
2. `GUARANTEED`인 CJ 송장만 CJ ONE 양식으로 출력한다.
3. 일반 등급과 서비스 등급이 누락된 CJ 송장은 일반 양식으로 출력한다.
4. 한 번에 일반·스타배송 송장이 섞여 있어도 각 송장에 맞는 ZPL을 순서대로 생성한다.
5. 스타배송 송장 출력만으로 피킹·패킹·출고 완료를 대신하지 않는다.
6. Box·주문·송장번호·서비스 등급과 출력 이력을 함께 보존한다.

## CAPA 초과 선언

센터가 발송 마감 약속을 정상적으로 처리하기 어려운 시간대를 `CAPA 초과`로 선언한다. 선언은 센터와 적용 시작·종료 시각을 기준으로 관리하며 자동 선언과 수동 선언을 구분한다.

```text
센터 선택
→ 기존 AUTO·MANUAL 일정 확인
→ 적용 시작 시각 선택
→ 종료 시각 확인
→ CAPA 초과 선언
→ 실행 시점 이후 유입 주문부터 적용
```

### 수동 선언 정책

1. 수동 선언의 종료 시각은 같은 날 `16:00`으로 고정한다.
2. 시작 시각은 종료 시각보다 이전이어야 한다.
3. 자동 선언 시간대인 금요일 16:00부터 일요일 23:59까지는 수동 선언할 수 없다.
4. 선언은 실행 시점 이후 유입되는 주문부터 적용한다.
5. 외부 취소 API가 없으므로 선언 후 취소할 수 없다.
6. 자동·수동 선언 일정과 성공·실패 결과를 조회할 수 있어야 한다.
7. 기존 수동 선언 앞에 빈 구간이 있으면 추가 선언할 수 있으며, 종료는 기존 선언 시작 직전으로 고정한다.

## 예외

| 예외 | 영향 | 확인 사항 |
|---|---|---|
| 스타배송 식별 누락 | 일반 주문으로 처리될 수 있음 | 배송 방식·연동 원본 확인 |
| 발송 마감일 누락 | 작업 우선순위를 판단할 수 없음 | 주문 수집 결과 재확인 |
| 마감 초과 | 도착보장 약속에 영향 | 미처리 단계·센터 CAPA 확인 |
| 서비스 등급 불일치 | 잘못된 송장 양식 출력 | `carrierServiceClassNm` 확인 |
| CAPA 선언 시간 중복 | 적용 구간 판단이 모호함 | AUTO·MANUAL 일정 확인 |
| 수동 선언 취소 요청 | 시스템에서 취소할 수 없음 | 선언 전 적용 시각 재확인 |
| Feature Flag 비활성 | 배송 방식 필터·CAPA 메뉴가 보이지 않음 | 기능 활성화 상태 확인 |
