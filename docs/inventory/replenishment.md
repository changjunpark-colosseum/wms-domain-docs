# 보충

<div class="page-meta"><span>재고</span><span>피킹 재고 공급</span><span>10분</span></div>

보충은 보관로케이션(`STRG`)의 Stock을 피킹로케이션(`PICK`)으로 옮기는 목적성 이동이다.

```text
보관로케이션(STRG)
→ 보충 작업
→ 피킹로케이션(PICK)
→ 출고 피킹에서 사용
```

## 이동과의 차이

| 이동 | 보충 |
|---|---|
| 재배치 자체가 목적 | 피킹 가능 수량 확보가 목적 |
| 허용된 Location 간 이동 | 보관로케이션(`STRG`) → 피킹로케이션(`PICK`) |
| 사용자가 수량 지정 | 현재량·목표량·출고 수요로 권장 수량 산출 가능 |

## 작업 흐름

<div class="flow-strip"><span>보충 필요 상품 조회</span><i>→</i><span>원천 Stock 선택</span><i>→</i><span>작업 생성·할당</span><i>→</i><span>출발 Location·상품 스캔</span><i>→</i><span>피킹로케이션(PICK) 스캔</span><i>→</i><span>적재·완료</span></div>

## 권장 수량

```text
권장 보충량
= min(
  피킹로케이션(PICK) 목표수량 - 현재수량,
  피킹로케이션(PICK) 여유 용량,
  원천 가용수량,
  출고 필요수량
)
```

## 출고 유형과 보충

| 출고 유형 | 피킹 대상 Zone | 보충 판단 |
|---|---|---|
| B2C | 피킹로케이션(`PICK`) | 보관로케이션(`STRG`)에만 재고가 있으면 피킹지시 생성 전에 보충 필요 |
| B2B 기본 | 피킹로케이션(`PICK`) + 보관로케이션(`STRG`) | 보관로케이션(`STRG`)에서 직접 피킹할 수 있어 보충이 항상 선행하지 않음 |
| B2B 피킹 존 피킹 | 피킹로케이션(`PICK`) | 피킹로케이션(`PICK`) 재고가 부족하면 보충 필요 |

신청 화면의 전체 가용재고가 충분하더라도 작업 생성 시 허용된 Zone에 재고가 없으면 보충 필요 수량으로 판단한다.

## 정책

1. 보충 전후 센터 전체 Stock 수량은 변하지 않는다.
2. 원천은 사용 가능한 보관로케이션(`STRG`)의 가용 Stock이어야 한다.
3. 도착지는 피킹에 사용할 수 있는 Location이어야 한다.
4. 권장 수량은 원천 가용수량과 도착지 용량을 초과하지 않는다.
5. BOX·EA 단위가 다르면 동일한 UOM 환산 기준을 사용한다.
6. 보충 완료 후 피킹로케이션(`PICK`)의 가용수량을 갱신한다.
7. 긴급 보충은 원래 피킹 작업과 연결한다.
8. B2C와 `피킹 존 피킹` B2B 작업은 피킹로케이션(`PICK`) 가용재고를 기준으로 보충 필요 여부를 판단한다.
9. 피킹로케이션(`PICK`)·보관로케이션(`STRG`)을 모두 허용하는 B2B 작업에는 불필요한 선행 보충을 강제하지 않는다.

## 취소

보충 작업은 작업자가 시작하기 전까지만 취소할 수 있다.

```text
보충 대기·미시작 → 취소 가능, 계획 수량과 원천 Stock 복구
보충 시작        → 취소 불가, 진행·예외 절차로 종결
```

취소 가능한 작업은 취소 가능 상태 목록과 미완료 조건을 모두 충족해야 한다. 시작된 작업을 취소로 되돌려 원천 Stock을 중복 복구하지 않는다.

## 예외

- 원천 Stock 부족
- 잘못된 피킹로케이션(`PICK`)
- 도착 Location 용량 초과
- UOM 환산 불일치
- 보충 완료 전 피킹 재개
- 동일 부족 건에 중복 보충 작업 생성
- 이미 시작된 보충 작업 취소 시도
