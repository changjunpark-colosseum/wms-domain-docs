# LOT·유효기간

<div class="page-meta"><span>재고</span><span>상품 추적</span><span>9분</span></div>

LOT와 유효기간은 같은 SKU의 실물을 서로 다른 재고 그룹으로 구분하는 값이다.

## 용어

| 용어 | 설명 |
|---|---|
| LOT | 같은 생산·입고 특성을 공유하는 재고 그룹 |
| 제조일 | 상품을 생산한 날짜 |
| 유효기간 | 상품을 정상적으로 사용할 수 있는 마지막 날짜 |
| 입고회차 | 같은 SKU가 창고에 들어온 물류 이력 단위 |

## 조회

재고 조회에서는 SKU 합계와 함께 LOT·유효기간별 상세 수량을 확인할 수 있어야 한다.

```text
SKU-A 총 30EA
├─ LOT-01 / 2027-06-30 / 10EA
└─ LOT-02 / 2027-12-31 / 20EA
```

## 출고 가능 최소 유효기간

CGKR은 유효기간 관리 상품의 피킹 대상을 조회할 때 상품의 최소 잔여기간에 창고 작업 버퍼 3일을 더한다.

```text
출고 가능 최소 유효기간
= 오늘 + 상품 최소 잔여기간(expiryMinDay) + 창고 작업 버퍼 3일
```

B2B에서 `창고 작업일 제외`를 선택하면 3일 버퍼를 더하지 않는다. 시간대 정보가 없으면 `Asia/Seoul`을 기준으로 날짜를 계산한다.

| 조건 | 출고 가능 최소 유효기간 |
|---|---|
| 일반·B2C | 상품 최소 잔여기간 + 3일 |
| B2B 창고 작업일 포함 | 상품 최소 잔여기간 + 3일 |
| B2B 창고 작업일 제외 | 상품 최소 잔여기간 |

## 피킹 Stock 할당 순서

같은 상품의 후보 Stock은 다음 순서로 조회한다.

```text
유효기간 빠른 순
→ LOT 빠른 순
→ UOM 코드 우선순위
→ 가용수량이 작은 Stock 순
```

유효기간이나 LOT가 `NULL`·빈 값인 Stock은 값이 있는 Stock보다 뒤에 배치한다. 따라서 CGKR의 피킹 할당은 단순 입고일 FIFO가 아니라 유효기간·LOT·UOM·잔량을 함께 사용하는 순서다.

## 정책

1. LOT·유효기간 관리 여부는 SKU에서 정의한다.
2. 관리 대상 SKU는 입고 검수에서 값을 입력·확정한다.
3. LOT·유효기간이 다르면 별도 Stock으로 관리한다.
4. 이동·보충 후에도 LOT·유효기간을 유지한다.
5. 유효기간 관리 상품은 상품 최소 잔여기간과 창고 작업 버퍼를 충족한 Stock만 출고 후보로 조회한다.
6. HOLD·폐기 시 대상 LOT를 정확히 지정한다.
7. 조회·다운로드에서 LOT·유효기간 조건을 동일하게 적용한다.
8. 출고 후보는 유효기간·LOT·UOM 우선순위·가용수량 순으로 정렬한다.
9. B2B 창고 작업일 제외 여부를 피킹 시뮬레이션과 실제 작업 생성에 동일하게 적용한다.


## 값 변경

이미 입고·출고 이력이 있는 LOT·유효기간을 단순히 덮어쓰면 과거 수불 이력이 달라진다.

- 변경 전후 값을 보존한다.
- 변경 사유와 처리자를 기록한다.
- 이동 중·출고 작업 중인 재고는 변경을 제한한다.
- 수량을 다른 LOT으로 옮기는 경우 조정 사건으로 기록한다.

## 예외

- 필수 LOT·유효기간 누락
- 동일 실물에 서로 다른 LOT 입력
- 유효기간이 제조일보다 빠름
- 출고 제한일을 지난 재고가 가용으로 남음
- 작업 중 LOT 변경으로 피킹 대상이 달라짐
- 창고 작업 버퍼를 적용하지 않아 최소 잔여기간 미달 Stock이 할당됨
- 시뮬레이션과 실제 피킹 생성의 창고 작업일 제외 조건 불일치
