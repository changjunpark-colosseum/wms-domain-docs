# 상품과 SKU

<div class="page-meta"><span>기준정보</span><span>핵심 개념</span><span>10분</span></div>

**Product는 판매 관점의 상품을, SKU는 재고로 구분해 취급할 최소 단위를 나타냅니다.** 색상·사이즈처럼 물류 처리가 달라지는 옵션 조합은 보통 서로 다른 SKU가 됩니다.

## 왜 구분할까?

한 상품 페이지에 검정·흰색 티셔츠가 함께 보이더라도 창고에서는 각각의 수량과 바코드를 따로 관리해야 합니다. Product는 고객에게 보여줄 구성을 묶고, SKU는 입고·재고·출고가 참조할 식별 단위를 제공합니다.

| 객체 | 답하는 질문 | 예시 |
|---|---|---|
| Product | 무엇을 판매하는가? | 데일리 티셔츠 |
| SKU | 무엇을 따로 세고 출고하는가? | 검정/M, 흰색/L |
| SKU Instance | 어떤 LOT·유효기간·입고회차의 실물인가? | LOT A, 2027-12-31 |
| Bundle | 어떤 SKU를 몇 개 묶어 판매하는가? | 티셔츠 1 + 양말 2 |

## 표준 흐름

<div class="flow-strip"><span>Product 정의</span><i>→</i><span>옵션 구성</span><i>→</i><span>SKU 생성</span><i>→</i><span>바코드·UOM 지정</span><i>→</i><span>입출고에서 참조</span></div>

## 바코드와 UOM

- **바코드**는 스캔으로 SKU를 찾는 식별 수단입니다. 하나의 SKU가 여러 바코드를 가질 수 있습니다.
- **UOM(Unit of Measure)**은 수량의 단위입니다. `1 BOX = 12 EA`처럼 환산 관계를 가질 수 있습니다.
- 바코드와 UOM은 SKU를 설명하는 속성이지 실제 재고 수량 자체가 아닙니다.

::: warning 구현 시 고려사항
UOM 환산은 입고·재고·출고에서 같은 기준을 사용해야 합니다. 화면마다 BOX와 EA 변환을 따로 구현하면 이중 환산이나 반올림 불일치가 생기기 쉽습니다.
:::

## 상품 등록과 재고 추가

| 상품 등록 | 재고 추가 |
|---|---|
| 기준정보를 만듭니다. | 물리적으로 존재하는 수량을 기록합니다. |
| 위치가 필요하지 않습니다. | 반드시 창고·Location·상태가 필요합니다. |
| 수량을 바꾸지 않습니다. | Inventory와 Stock 또는 수불 이력을 바꿉니다. |

관리자 재고 추가는 일반 입고를 생략하는 예외 경로일 수 있습니다. 그렇더라도 `사유`, `처리자`, `Location`, `수량 변화 이력`이 남아야 합니다.

## 주요 정책

1. 운영 이력이 생긴 SKU 식별자는 임의로 재사용하지 않습니다.
2. 과거 주문·재고가 참조하는 SKU는 삭제보다 비활성화를 사용합니다.
3. SKU의 LOT·유효기간 관리 여부는 입고 시 Instance 생성 규칙에 영향을 줍니다.
4. Bundle 주문은 출고 전에 구성 SKU와 수량으로 전개돼야 합니다.

## 학습용 예시

`커피 캡슐 10개입`을 1 BOX 단위로 판매하더라도 창고가 EA 단위로 재고를 세면 `BOX 바코드 → SKU → 10 EA` 환산 규칙이 필요합니다. BOX 한 개를 입고했을 때 재고는 1이 아니라 기준 단위 10 EA로 증가할 수 있습니다.

## 확인 문제

1. 같은 Product에 속한 두 SKU의 재고를 합쳐서만 보여주면 어떤 문제가 생길까요?
2. 상품명이 바뀌어도 SKU 식별자를 유지해야 하는 이유는 무엇일까요?
3. Bundle을 하나의 실물 SKU로 관리하는 경우와 주문 시 구성품으로 푸는 경우의 차이는 무엇일까요?
