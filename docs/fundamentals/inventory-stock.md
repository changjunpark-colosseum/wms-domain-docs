# Inventory와 Stock

<div class="page-meta"><span>재고</span><span>상태 모델</span><span>12분</span></div>

WMS의 재고는 하나의 숫자가 아닙니다. **총량, 위치, 품질, 예약과 작업 상태를 함께 설명할 수 있어야 하는 상태 모델**입니다.

## 두 가지 관점

| 관점 | 설명 | 대표 질문 |
|---|---|---|
| Inventory | 상품·SKU별 장부 수량 | 이 SKU가 창고에 총 몇 개 존재하는가? |
| Stock | 특정 Location·LPN·상태의 실물 수량 | 그중 어디에 어떤 상태로 몇 개 있는가? |

시스템에 따라 이름은 달라질 수 있습니다. 중요한 것은 **집계된 장부와 위치별 상세 실물을 구분하고 서로 대사할 수 있는가**입니다.

## 재고 항등식

<InventoryEquation />

```text
SOH = Available + Allocated + WIP + Unavailable
Available = SOH - Allocated - WIP - Unavailable
```

- `SOH`: 창고가 보유한 총량
- `Available`: 새 주문에 약속할 수 있는 자유 재고
- `Allocated`: 주문에 예약됐지만 아직 저장 위치에 있는 재고
- `WIP`: 피킹·패킹·이동·반환 작업 중인 재고
- `Unavailable`: 품질 보류·불량·미적치 등 출고할 수 없는 재고

## 총량을 바꾸는 사건과 바꾸지 않는 사건

| 사건 | SOH | 위치·상태 |
|---|---:|---|
| 입고확정 | 증가 | 입고·미적치 상태 생성 |
| 적치 | 유지 | 저장 Location으로 이동 |
| 할당 | 유지 | Available → Allocated |
| 피킹 | 유지 | Allocated → WIP |
| 출고확정 | 감소 | 창고 밖으로 이탈 |
| 단순 이동·보충 | 유지 | Location 변경 |
| 폐기확정 | 감소 | 사유를 가진 재고 이탈 |

## 품질과 가용성

품질이 정상이라고 언제나 Available은 아닙니다. 아직 적치되지 않았거나 다른 작업에 예약된 재고는 정상 품질이어도 출고에 사용할 수 없습니다. 반대로 SOH에 포함되어도 HOLD나 불량이면 Unavailable입니다.

::: tip 일반 원칙
재고 상태를 하나의 열에 모두 넣기보다 `물리 흐름`, `품질`, `예약·작업` 축을 분리하면 전이와 예외를 설명하기 쉽습니다.
:::

## 주요 정책

1. 모든 가용성 버킷의 합은 SOH와 일치해야 합니다.
2. 신규 할당은 실제 Available을 초과할 수 없습니다.
3. 피킹은 출고확정 전까지 SOH를 줄이지 않습니다.
4. 취소는 반대 이벤트로 WIP 또는 Allocated를 복구합니다.
5. 모든 증감은 원인 사건과 연결되어야 합니다.

## 예외 상황

- **음수 재고:** 허용 여부와 보상 책임을 명시해야 합니다.
- **중복 이벤트:** 같은 입고확정이나 출고확정이 재시도돼도 한 번만 반영해야 합니다.
- **위치 불일치:** 장부 수량과 Location 상세 합계가 다르면 대사 대상입니다.
- **부분 처리:** 원본과 처리분의 합이 이전 총량과 같아야 합니다.
