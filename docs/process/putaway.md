# 적치

<div class="page-meta"><span>입고</span><span>Location</span><span>9분</span></div>

적치는 **입고확정된 재고를 조건에 맞는 보관 Location으로 이동해 찾을 수 있고 사용할 수 있는 상태로 만드는 작업**입니다.

## 시작 조건

- 입고확정된 LPN 또는 재고 묶음이 존재합니다.
- 현재 위치와 남은 적치 수량이 명확합니다.
- 대상 Location의 용도·수용량·혼적 규칙을 확인할 수 있습니다.

## 표준 흐름

<div class="flow-strip"><span>적치 대상 생성</span><i>→</i><span>Location 추천</span><i>→</i><span>LPN 스캔</span><i>→</i><span>목적지 스캔</span><i>→</i><span>수량 이동</span><i>→</i><span>가용성 재계산</span></div>

## Location 추천 기준

- 상품 크기·중량과 Location 수용량
- 온도·위험물·품질 Zone 제약
- 같은 SKU·LOT 재고와의 인접성
- 출고 빈도와 피킹 동선
- 혼적 허용 여부와 남은 용량

추천은 작업자의 판단을 돕는 정책입니다. 다른 Location을 선택할 수 있다면 변경 사유와 권한을 남기는 편이 좋습니다.

## 완료 조건

1. 출발 Location의 처리 수량이 감소했습니다.
2. 도착 Location에 같은 수량이 증가했습니다.
3. LPN·LOT·유효기간 등 정체성이 보존됐습니다.
4. 작업 잔량이 0이거나 승인된 예외로 종결됐습니다.
5. 정상 STORAGE 재고라면 Available 후보가 됩니다.

## 부분 적치

```text
검수 완료 LPN 20 EA
├─ Location A 적치 12 EA
└─ Location B 적치 8 EA

12 + 8 = 20
```

부분 적치가 가능하다면 회차별 수량과 잔량을 보존하고, 중복 완료가 총량을 늘리지 않도록 해야 합니다.

## 예외 상황

- 추천 Location이 가득 찼습니다.
- 스캔한 Location이 SKU·온도·중량 정책을 위반합니다.
- LPN 실물 수량과 시스템 잔량이 다릅니다.
- 작업 중 일부만 적치하고 교대를 종료합니다.
- 목적지 스캔 뒤 네트워크가 끊겼습니다.

::: warning 구현 시 고려사항
출발지 감소와 도착지 증가는 하나의 원자적 이동이어야 합니다. 둘 중 하나만 성공하면 재고가 사라지거나 복제됩니다.
:::

## 확인 문제

1. 적치완료 전에 Available로 만드는 것과 완료 후 만드는 것의 차이는 무엇일까요?
2. 부분 적치 재시도에서 중복 증가를 막으려면 어떤 식별자가 필요할까요?
3. Location 추천을 강제 정책으로 사용할 때 생길 수 있는 운영 문제는 무엇일까요?
