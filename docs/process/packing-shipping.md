# 패킹·송장·출고확정

<div class="page-meta"><span>출고</span><span>배송</span><span>11분</span></div>

패킹은 **피킹된 실물과 주문 내용을 대사해 배송 가능한 박스 단위로 확정하는 과정**입니다. 송장은 외부 운송 식별자이고, 출고확정은 재고 총량이 창고를 떠나는 경계 사건입니다.

## 표준 흐름

<div class="flow-strip"><span>주문·운반체 확인</span><i>→</i><span>내용물 검수</span><i>→</i><span>박스 선택</span><i>→</i><span>봉함·중량</span><i>→</i><span>송장 발번</span><i>→</i><span>상차·출고확정</span></div>

## 핵심 객체

| 객체 | 역할 |
|---|---|
| Packing Work | 검수·포장 작업 이력 |
| Parcel·Box | 실제 포장 단위와 내용물 |
| Packing Slip | 박스 안의 구성 안내 문서 |
| Shipping Label | 택배사·주소·서비스 정보 라벨 |
| Tracking Number | 외부 운송사가 추적하는 송장번호 |

주문 하나가 여러 박스로 나뉘거나 여러 주문이 합포장될 수 있으므로 주문, 박스와 송장의 관계를 명시해야 합니다.

## 패킹 검수

피킹 완료만 믿고 봉함하지 않습니다. SKU, 수량, 주문, 운반체를 다시 대사해 누락과 혼입을 찾습니다. 시리얼 관리 상품은 이 단계에서 주문·박스·시리얼을 연결할 수 있습니다.

## 송장 상태

```text
REQUESTED → ISSUED → PRINTED → ATTACHED → SHIPPED
                 └→ VOID
```

재출력은 같은 송장의 라벨을 다시 인쇄하는 것이고, 재발번은 기존 송장을 무효화하고 새 번호를 받는 것입니다. 둘을 구분해야 중복 배송과 추적 혼선을 막을 수 있습니다.

## 출고확정

- 상차 또는 택배사 인계가 완료됐습니다.
- 박스와 송장의 연결이 유효합니다.
- 출고 수량이 SOH에서 한 번만 감소합니다.
- 주문·작업·배송 상태가 함께 갱신됩니다.
- 실패한 외부 통지는 재시도 가능해야 합니다.

## 예외 상황

- 피킹 수량과 주문 수량 불일치
- 잘못된 상품이 다른 주문 운반체에 혼입
- 중량·부피 제한 초과로 박스 분할
- 송장 발번 성공 후 응답 유실
- 라벨 훼손과 재출력
- 상차 완료 후 시스템 출고확정 실패

::: warning 구현 시 고려사항
송장 발번처럼 외부 시스템과 연결되는 작업은 타임아웃이 실패를 뜻하지 않을 수 있습니다. 요청 식별자로 결과를 조회하고 중복 발번을 막아야 합니다.
:::
