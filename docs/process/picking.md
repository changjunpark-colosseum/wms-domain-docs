# 피킹

<div class="page-meta"><span>출고</span><span>작업</span><span>11분</span></div>

피킹은 **할당된 재고를 지정 Location에서 꺼내 주문 또는 후속 분류 단위로 이동하는 물리 작업**입니다.

## 시작 조건

- 할당된 주문 또는 웨이브가 있습니다.
- 피킹 대상 Location·SKU·수량을 확인할 수 있습니다.
- 작업자와 Cart·Tote 같은 운반 단위가 준비돼 있습니다.
- 대상 재고가 다른 물리 작업에 잠겨 있지 않습니다.

## 표준 흐름

<div class="flow-strip"><span>작업 수락</span><i>→</i><span>Location 이동</span><i>→</i><span>Location 스캔</span><i>→</i><span>SKU·LPN 스캔</span><i>→</i><span>수량 확인</span><i>→</i><span>운반체 이동</span></div>

## 대표 피킹 전략

| 전략 | 방식 | 적합한 상황 |
|---|---|---|
| 개별 피킹 | 주문 하나씩 완료 | 주문 수가 적거나 고가품 |
| 배치 피킹 | 여러 주문의 같은 SKU를 함께 집품 | 소형 다빈도 주문 |
| 클러스터 피킹 | Cart 칸별로 주문을 동시에 분류 | 다품목 B2C |
| 총량 피킹 | SKU 총량을 집품 후 별도 분배 | 대량 주문 처리 |
| Zone 피킹 | 작업자가 담당 Zone만 처리 | 대형 창고·전문화 Zone |

## 재고 변화

피킹은 일반적으로 `Allocated → WIP` 이동입니다. 저장 Location 수량은 줄지만 SOH는 그대로입니다. 주문별 매칭이 뒤 단계에서 일어나는 총량 피킹이라면 벌크 수량과 분배 완료 수량을 별도로 대사해야 합니다.

## 주요 정책

1. Location과 상품을 모두 확인해 오피킹을 줄입니다.
2. 작업 시작 시 물리 충돌을 막는 잠금 범위를 정의합니다.
3. 부분 피킹은 완료 수량, 부족 수량과 잔량을 분리합니다.
4. 작업 중단·이탈 시 잠금과 WIP를 함께 복구합니다.
5. 스캔 생략이나 관리자 완료는 사유·권한·이력을 남깁니다.

## 예외 상황

| 예외 | 질문 |
|---|---|
| 실물 부족 | 시스템 수량을 즉시 조정할지, 실사 작업을 만들지? |
| 오피킹 | 원위치 putback과 재피킹을 어떻게 연결할지? |
| 라벨 미인식 | 대체 식별과 수동 입력 권한은 누구에게 있는지? |
| 작업 교대 | 처리분·잔량·운반체를 누구에게 인계하는지? |
| 네트워크 단절 | 오프라인 스캔을 어떤 순서와 멱등키로 동기화할지? |

## 확인 문제

1. 할당과 피킹 잠금을 같은 시점에 걸면 어떤 문제가 생길까요?
2. 총량 피킹에서 벌크 집품 수량과 주문 분배 수량은 어떻게 대사할까요?
3. 피킹 부족을 곧바로 재고 조정으로 처리하면 어떤 증거가 사라질까요?
