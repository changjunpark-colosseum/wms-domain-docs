# 출고 프로세스

<div class="page-meta"><span>출고</span><span>프로세스</span><span>12분</span></div>

출고는 **주문이 요구하는 SKU와 수량을 창고 재고에 연결하고, 정확히 집품·포장해 물리적으로 창고 밖으로 보내는 과정**입니다.

## 표준 업무 흐름

<div class="flow-strip"><span>주문 수신</span><i>→</i><span>재고 할당</span><i>→</i><span>웨이브·작업 생성</span><i>→</i><span>피킹</span><i>→</i><span>패킹·송장</span><i>→</i><span>상차·출고확정</span></div>

## 주문과 출고 지시

판매 주문과 창고 출고 주문은 같은 객체가 아닐 수 있습니다. 한 주문이 여러 창고나 배송으로 분할될 수 있고, 여러 주문을 한 출고 작업으로 묶을 수도 있습니다.

## 할당

할당은 주문 수량을 Available 재고에 예약합니다. 일반적인 선택 기준은 FEFO·FIFO, Location 우선순위, 재고 속성, 주문 마감시각과 작업 효율입니다.

```text
Available 30 EA
주문 A 8 EA 할당
→ Available 22 EA
→ Allocated 8 EA
→ SOH 30 EA 유지
```

## 웨이브와 작업

웨이브는 배송 마감, 주문 유형, Zone과 작업 부하가 비슷한 주문을 묶어 실행 단위로 만듭니다. 웨이브가 없어도 작업 생성과 주문의 관계는 추적돼야 합니다.

## 완료 경계

| 단계 | 재고 의미 |
|---|---|
| 할당 | 주문에 예약됐지만 저장 위치에 존재 |
| 피킹 | 저장 위치를 떠나 작업 중 |
| 패킹 | 박스와 주문 내용물이 연결됨 |
| 송장 | 외부 운송 식별자가 연결됨 |
| 출고확정 | 물리적으로 창고를 떠나 SOH 감소 |

## 주요 정책

1. Available 이상을 신규 할당하지 않습니다.
2. 작업은 주문·SKU·재고 묶음과 추적 가능하게 연결합니다.
3. 피킹·패킹은 출고확정 전까지 SOH를 줄이지 않습니다.
4. 취소 시 진행 단계에 맞는 해제·putback·무효화가 필요합니다.
5. 출고확정과 송장 이벤트는 재시도돼도 한 번만 반영합니다.

## 예외 상황

- 재고 부족과 부분 할당
- 주문 변경·취소
- 피킹 부족·오피킹
- 패킹 검수 불일치
- 송장 발번 실패·재출력
- 상차 후 출고확정 실패

## 확인 문제

1. 주문 1건과 출고 작업 1건을 항상 1:1로 만들면 어떤 제약이 생길까요?
2. 송장을 발번했지만 상차하지 않은 상품은 SOH에 포함될까요?
3. 피킹 후 주문이 취소되면 어떤 보상 작업이 필요할까요?
