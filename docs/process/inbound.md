# 입고 프로세스

<div class="page-meta"><span>입고</span><span>프로세스</span><span>12분</span></div>

입고는 **외부에서 도착한 실물을 주문·상품정보와 비교하고, 창고가 책임지는 재고로 편입하는 과정**입니다.

## 시작 조건

- 입고 예정 또는 구매·이동 주문이 존재합니다.
- SKU, UOM, LOT·유효기간 관리 기준을 확인할 수 있습니다.
- 도착 창고와 입하 도크가 정해져 있습니다.
- 예외를 처리할 담당자와 격리 Location이 준비돼 있습니다.

## 표준 업무 흐름

<div class="flow-strip"><span>입고 예정</span><i>→</i><span>도크 접안·하역</span><i>→</i><span>입하 등록</span><i>→</i><span>검수</span><i>→</i><span>입고확정</span><i>→</i><span>적치 대기</span></div>

### 입고 예정

ASN이나 입고 주문에는 도착 예정일, 공급처, SKU, 기대 수량과 포장 단위가 포함됩니다. 예정 정보는 작업을 준비하는 기준이며 실제 재고는 아닙니다.

### 입하

차량·팔레트·박스가 도크에 도착했음을 기록합니다. 외관 파손과 봉인 상태를 확인하고, 검수할 취급 단위를 분리합니다.

### 검수

실제 SKU·수량·LOT·유효기간·품질을 예정 정보와 비교합니다. 일치하지 않는 수량은 정상분과 섞지 않고 예외로 분리합니다.

### 입고확정

검수된 수량을 창고의 SOH에 편입합니다. 이 시점에 LPN이나 SKU Instance가 생성될 수 있습니다. 아직 적치되지 않았다면 보통 Unavailable입니다.

## 핵심 상태

```text
PLANNED → ARRIVED → INSPECTING → RECEIVED → PUTAWAY_PENDING → COMPLETED
                         └──────→ EXCEPTION
```

상태명은 시스템마다 다르지만 `예정`, `물리 도착`, `검수`, `총량 편입`, `적치 완료`의 경계는 구분해야 합니다.

## 주요 정책

1. 예정 수량과 실제 검수 수량을 덮어쓰지 않고 둘 다 보존합니다.
2. 초과·부족·오입고·파손은 사유와 승인 결과를 기록합니다.
3. 같은 입고확정 요청이 재시도돼도 SOH가 두 번 증가하지 않습니다.
4. LOT·유효기간 관리 SKU는 필수값을 확인한 뒤 확정합니다.
5. 입고확정과 적치완료를 같은 사건으로 합치지 않습니다.

## 예외 상황

| 예외 | 처리 원칙 |
|---|---|
| 예정 부족 | 실제 수량만 확정하고 미입고 잔량의 종결 여부를 결정합니다. |
| 예정 초과 | 승인 전까지 초과분을 격리합니다. |
| 미등록 SKU | 임시 식별 후 상품 등록·매핑 절차로 보냅니다. |
| 파손·불량 | HOLD 또는 DEFECT로 분리하고 정상 재고와 섞지 않습니다. |
| 중복 스캔 | 취급 단위와 작업 기준으로 중복 반영을 막습니다. |
