# 운영 주체와 역할

<div class="page-meta"><span>시작하기</span><span>사용자</span><span>역할·책임</span></div>

WMS는 시스템 기능만으로 움직이지 않는다. 화주사가 물류를 요청하고, 센터 관리자가 작업을 계획하며, 현장 작업자가 실물을 처리하고, 운송사가 배송을 이어받는다. 같은 기능도 누가 요청하고 실행하고 확인하는지에 따라 책임이 달라진다.

## 먼저 구분할 것

| 구분 | 의미 | 예시 |
|---|---|---|
| 업무 주체 | 상품·재고·작업에 책임을 지는 조직이나 사람 | 화주사, 센터, 작업자 |
| 조직 | 계정과 데이터가 귀속되는 업무 단위 | 화주사, 물류센터, 운송사 |
| 계정 | CGKR에 로그인하거나 API를 호출하는 식별자 | 관리자 계정, PDA 작업자, 연동 계정 |
| 역할 | 계정이 수행할 수 있는 행위의 묶음 | 조회, 작업 실행, 승인, 설정 관리 |
| 작업 할당 | 특정 작업을 현재 누가 수행하는지 나타내는 관계 | 피킹 작업 A → 작업자 B |

센터는 작업 장소이자 운영 단위이고, 작업자는 센터에 속해 실제 업무를 수행하는 사람이다. `센터`와 `센터 작업자`를 같은 사용자로 취급하지 않는다.

## 주체 관계

<div class="flow-strip"><span>외부 채널·COLO<br><small>상품·주문 발생</small></span><i>→</i><span>화주사·셀러<br><small>상품·재고 소유</small></span><i>→</i><span>CGKR<br><small>요청·상태 관리</small></span><i>→</i><span>물류센터<br><small>실물 보관·작업</small></span><i>→</i><span>택배사·운송사<br><small>집하·배송</small></span></div>

이 그림은 업무 관계를 단순화한 것이다. 실제 상품·주문 데이터는 외부 채널·COLO에서 연동을 통해 CGKR로 들어올 수 있고, 출고·송장 결과는 반대 방향으로 돌아간다.

물류센터 안에서는 책임이 다시 나뉜다.

```text
물류센터
├─ 센터 관리자
│  ├─ 작업 계획·생성·할당
│  ├─ Location·설비·운영 기준 관리
│  └─ 예외 확인·승인·재고 조정
└─ 현장 작업자
   ├─ 입하·검수·적치
   ├─ 이동·보충·재고 실사
   ├─ 피킹·패킹·상차
   └─ 반입·반품 검수·양품화
```

## 도메인별 책임

| 도메인 | 요청·정보 제공 | 계획·통제 | 현장 실행 | 확인·결과 소비 |
|---|---|---|---|---|
| 상품 | 화주사·셀러·외부 채널 | 화주사·연동 시스템 | - | 센터 관리자·작업자 |
| 입고 | 화주사 | 센터 관리자 | 입하·검수·적치 작업자 | 화주사·센터 관리자 |
| 재고 | 입고·출고·반품 사건 | 센터 관리자 | 이동·보충·실사 작업자 | 화주사·센터 관리자 |
| 출고 | 셀러·외부 채널·화주사 | 센터 관리자 | 피킹·패킹·상차 작업자 | 화주사·외부 채널 |
| 배송·송장 | 출고 주문·배송 정보 | 센터 관리자·연동 시스템 | 패킹·상차 작업자 | 택배사·화주사·외부 채널 |
| 반품 | 셀러·외부 채널·화주사 | 센터 관리자 | 반입·검수·양품화 작업자 | 화주사 확인 후 재입고·폐기·반송 |

한 주체가 여러 역할을 맡을 수 있지만 요청·실행·승인 기록은 구분해서 남긴다. 예를 들어 센터 관리자가 직접 재고 조정을 실행해도 `요청자`, `실행자`, `승인자`와 사유를 각각 추적할 수 있어야 한다.

## 권한과 데이터 범위

| 계정 유형 | 일반적인 데이터 범위 | 주요 행위 |
|---|---|---|
| 화주사 계정 | 자기 화주사의 상품·주문·재고·반품 | 요청, 조회, 결과 확인 |
| 센터 관리자 계정 | 담당 센터와 운영 대상 화주사의 데이터 | 설정, 작업 생성·할당, 예외 승인, 조정 |
| 현장 작업자 계정 | 소속 센터에서 할당받거나 가져올 수 있는 작업 | 스캔, 수량 입력, 작업 시작·완료, 예외 보고 |
| 연동 계정 | 연결된 화주사·채널과 허용된 API 범위 | 상품·주문 전달, 상태·송장·재고 결과 수신 |

권한은 메뉴 노출만 의미하지 않는다. 데이터 조회 범위와 상태 변경 권한을 함께 제한해야 한다.

1. 화주사 계정은 다른 화주사의 상품·재고·주문을 조회할 수 없다.
2. 센터 계정은 권한이 없는 센터의 Location·Stock·작업을 변경할 수 없다.
3. 작업자는 할당되지 않았거나 가져올 수 없는 작업을 임의로 완료할 수 없다.
4. 재고 조정·폐기·예외 완료처럼 재고에 영향을 주는 행위는 사유와 수행자를 남긴다.
5. API 연동 권한과 사람의 화면 권한을 분리한다.

## 작업 기록에 남길 사람

모든 작업은 결과뿐 아니라 책임 주체를 추적할 수 있어야 한다.

| 기록 | 답해야 하는 질문 |
|---|---|
| 요청자 | 누가 이 입고·출고·반품을 요청했는가? |
| 생성자·할당자 | 누가 작업을 만들고 담당자를 정했는가? |
| 작업자 | 누가 실물을 스캔하고 처리했는가? |
| 승인자·확인자 | 누가 조정·폐기·반품 처분을 승인했는가? |
| 소속 범위 | 어느 화주사와 센터의 업무인가? |
| 처리 시각·사유 | 언제, 어떤 이유로 상태와 수량이 바뀌었는가? |
