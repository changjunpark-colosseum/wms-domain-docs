# WMS 이해하기

<div class="page-meta"><span>시작하기</span><span>개요</span><span>5분</span></div>

WMS(Warehouse Management System)는 물류센터 안에서 **어떤 상품이, 얼마나, 어디에 있고, 어떤 작업을 거쳐 이동했는지** 관리하는 시스템이다.

주문만 관리하는 시스템과 달리 WMS는 작업자가 실제로 스캔한 상품·Location·수량과 작업 상태를 함께 기록한다. 그래서 상품 정보, 장부 재고, 실물 재고와 입출고 작업을 서로 구분하면서도 하나의 흐름으로 연결해야 한다.

## WMS가 답해야 하는 질문

| 질문 | 담당 도메인 |
|---|---|
| 무엇을 보관하는가? | 상품 |
| 수량이 얼마나 존재하는가? | Inventory |
| 실물이 어디에 있는가? | Stock·Location |
| 센터에 어떻게 들어오는가? | 입고 |
| 주문 상품을 어떻게 찾아 보내는가? | 출고 |
| 어떤 택배사와 송장으로 이동하는가? | 배송·송장 |
| 되돌아온 상품을 어떻게 처리하는가? | 반품 |

## 문서 읽는 순서

처음이라면 다음 순서로 읽는 것이 좋다.

```text
전체 도메인 흐름
→ 핵심 용어
→ 상품
→ Inventory·Stock·Location
→ 입고
→ 출고
→ 배송·송장
→ 반품
```

각 문서는 다음 네 가지를 중심으로 설명한다.

1. 객체가 무엇인지
2. 작업이 어떤 순서로 진행되는지
3. 수량과 상태가 언제 변경되는지
4. 정상 처리할 수 없는 경우를 어떻게 남기는지

## 가장 중요한 구분

### 상품과 재고

상품을 등록해도 재고가 생기지 않는다. 상품은 무엇을 취급하는지 정의하고, 재고는 입고·조정·반품 양품화 같은 사건이 확정될 때 생성된다.

### Inventory와 Stock

Inventory는 증감 사건을 반영한 장부 수량이고, Stock은 특정 Location에 존재하는 실물 수량과 상태다. 두 값은 서로 대사할 수 있어야 하지만 같은 객체는 아니다.

### 작업 완료와 재고 반영

피킹·패킹처럼 물류 작업이 끝난 시점과 Inventory가 최종 증감하는 시점은 구분한다. 하나의 사건을 여러 단계에서 중복 반영하면 재고가 이중으로 증가하거나 감소한다.
