# WMS 한눈에 보기

<div class="page-meta"><span>입문</span><span>전체 흐름</span><span>8분</span></div>

WMS(Warehouse Management System)는 **창고 안의 실물과 작업을 정확한 위치·수량·상태로 연결하는 시스템**입니다. 주문을 저장하는 것만으로는 부족합니다. 어떤 상품이 어느 위치에 있고, 지금 출고 가능한지, 누가 무엇을 옮겼는지를 계속 설명할 수 있어야 합니다.

## WMS가 답해야 하는 질문

| 질문 | 대표 정보 |
|---|---|
| 무엇이 들어왔는가? | Product, SKU, LOT, 유효기간 |
| 얼마나 존재하는가? | SOH, Available, Allocated, WIP |
| 어디에 있는가? | Warehouse, Zone, Location, LPN |
| 무엇을 해야 하는가? | 입고·적치·보충·피킹·패킹 작업 |
| 누가 언제 바꿨는가? | 작업자, 이벤트, 수불 이력, 사유 |
| 무엇이 나갔는가? | 출고 주문, 박스, 송장, 출고확정 |

## 전체 물류 흐름

<DomainJourney />

1. **상품**은 취급할 대상을 정의합니다.
2. **입고**는 도착한 실물을 검사하고 재고 총량에 편입합니다.
3. **재고**는 수량·위치·품질·사용 가능성을 유지합니다.
4. **출고**는 주문에 맞춰 재고를 예약하고 집품·포장·발송합니다.
5. **반품**은 돌아온 상품을 다시 판정해 재입고·폐기·반송합니다.
6. **정산**은 각 활동을 계약 기준의 사용량과 비용으로 환산합니다.

## 기준정보와 실행정보

WMS를 이해할 때 가장 먼저 나눌 경계입니다.

| 구분 | 의미 | 예시 |
|---|---|---|
| 기준정보 | 여러 작업이 공통으로 참조하는 정의 | SKU, 바코드, UOM, 창고, Location |
| 실행정보 | 실제 사건으로 생성되고 상태가 변하는 정보 | 입고 주문, LPN, 피킹 작업, 박스, 송장 |

상품을 등록했다고 재고가 생기지 않는 이유도 이 경계에 있습니다. `SKU`는 무엇을 셀지 정의하고, `Stock`은 실제 물건이 특정 위치에 존재함을 나타냅니다.

## 세 가지 관점으로 읽기

### 객체

무엇을 고유하게 식별하는지 확인합니다. 주문, 작업, 재고 묶음, 위치, 박스는 서로 다른 객체입니다.

### 상태

객체가 어떤 사건을 거쳐 바뀌는지 확인합니다. 상태명보다 **누가 어떤 조건에서 전이를 일으키는가**가 중요합니다.

### 불변식

구현이 달라도 항상 지켜져야 하는 규칙입니다.

- 이동 전후의 총수량은 보존됩니다.
- 같은 요청을 재시도해도 수량이 두 번 반영되지 않습니다.
- 모든 수량 변화는 원인과 작업자를 추적할 수 있습니다.
- 출고할 수 없는 재고는 정상 가용 재고와 구분됩니다.

::: tip 학습용 관점
화면 메뉴의 순서를 외우기보다 `객체 → 사건 → 상태 → 불변식` 순서로 읽으면 새로운 WMS도 빠르게 이해할 수 있습니다.
:::

## 확인 문제

1. 상품을 등록했는데 왜 바로 재고 조회에 수량이 나타나면 안 될까요?
2. 피킹이 끝났지만 아직 출고확정 전인 상품은 창고 총량에 포함될까요?
3. 재고 이동이 실패했을 때 출발지와 도착지 수량은 어떤 상태여야 할까요?
