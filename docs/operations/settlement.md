# 물류 정산

<div class="page-meta"><span>정산</span><span>비용 모델</span><span>10분</span></div>

물류 정산은 **입고·보관·출고·반품 같은 활동을 계약 요율과 결합해 재현 가능한 비용으로 만드는 과정**입니다.

## 표준 흐름

<div class="flow-strip"><span>계약·요율</span><i>→</i><span>사용량 수집</span><i>→</i><span>비용 계산</span><i>→</i><span>조정·검토</span><i>→</i><span>명세서 발행</span><i>→</i><span>결제·마감·대사</span></div>

## 핵심 객체

| 객체 | 의미 |
|---|---|
| Contract·Rate | 서비스 코드별 단가·구간·유효기간 |
| Usage Record | 과금 대상 활동과 수량의 원본 |
| Charge Line | 요율을 적용한 비용 항목 |
| Adjustment | 할인·추가 비용·정정과 사유 |
| Billing Statement | 고객에게 발행하는 기간별 명세서 |
| Reconciliation | 사용량·비용·결제 결과 대사 |

## 대표 사용량

- 입고: 입고 건, SKU 라인, 수량, 팔레트, 검수 작업
- 보관: 일별 재고 수량, 부피, 팔레트·Location 점유
- 출고: 주문, 피킹 라인, 박스, 부자재, 배송비
- 반품: 반입, 검수, 양품화, 폐기 작업
- 부가 작업: 라벨링, 세트 조립, 재포장, 긴급 처리

## 계산 원칙

```text
Charge = Usage × Effective Rate + Adjustment + Tax
```

같은 서비스 코드라도 계약 기간, 물량 구간, 센터, 배송 권역과 상품 속성에 따라 요율이 달라질 수 있습니다. 계산 결과만 저장하지 말고 어떤 사용량과 요율을 적용했는지 재현할 수 있어야 합니다.

## 주요 정책

1. 계약 요율, 사용량, 계산 결과와 수동 조정을 분리합니다.
2. 수동 조정은 사유·근거·처리자와 승인 이력을 가집니다.
3. 발행 후 변경은 회수·정정·재발행 이력을 남깁니다.
4. 물류 사건과 Usage Record 연결이 중복 과금을 만들지 않습니다.
5. 결제·세금계산서·정산 마감은 외부 결과와 대사합니다.

## 예외 상황

- 계약 변경일이 월 중간에 있는 경우
- 사용량 원본이 늦게 도착하거나 정정된 경우
- 배송비 외부 청구와 내부 예상 비용이 다른 경우
- 발행 후 누락 비용을 발견한 경우
- 결제 성공 응답이 유실된 경우

::: tip 일반 원칙
정산의 품질은 계산식보다 원본 물류 사건과 비용 항목 사이의 추적 가능성에서 결정됩니다.
:::

## 확인 문제

1. 비용 결과만 수동 수정하면 재계산에서 어떤 문제가 생길까요?
2. 사용량 이벤트의 멱등성이 정산에 중요한 이유는 무엇일까요?
3. 발행된 명세서를 직접 덮어쓰지 않고 정정 이력을 남겨야 하는 이유는 무엇일까요?
