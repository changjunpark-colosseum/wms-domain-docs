# 조정·실사·폐기

<div class="page-meta"><span>재고 운영</span><span>감사</span><span>11분</span></div>

조정, 실사와 폐기는 모두 수량에 영향을 줄 수 있지만 의미가 다릅니다.

| 업무 | 목적 | 핵심 결과 |
|---|---|---|
| 실사 | 장부와 실물을 비교 | 차이 발견·확정 |
| 조정 | 승인된 사유로 장부를 바로잡음 | Inventory 증감 이벤트 |
| 폐기 | 사용할 수 없는 실물을 실제 처분 | 증빙과 SOH 감소 |

## 실사 흐름

<div class="flow-strip"><span>범위 동결</span><i>→</i><span>Blind Count</span><i>→</i><span>차이 계산</span><i>→</i><span>재실사</span><i>→</i><span>승인</span><i>→</i><span>조정</span></div>

### Cycle Count

창고 전체를 멈추지 않고 위험도·회전율·차이 이력에 따라 일부 Location을 주기적으로 셉니다.

### Blind Count

작업자에게 장부 예상 수량을 숨기고 실물을 세게 해 숫자 맞추기 편향을 줄입니다.

## 재고 조정

조정은 원인을 덮어쓰는 기능이 아닙니다. 다음 정보를 가진 별도 이벤트여야 합니다.

- SKU·Location·LPN과 조정 전후 수량
- 증가·감소 구분
- 분실·파손·입력오류 등 사유 코드
- 요청자·승인자·처리시각
- 관련 실사·작업·증빙

## 폐기 흐름

<div class="flow-strip"><span>폐기 후보 격리</span><i>→</i><span>사유·수량 확인</span><i>→</i><span>승인</span><i>→</i><span>실제 처분</span><i>→</i><span>SOH 감소</span><i>→</i><span>증빙 보존</span></div>

폐기 Zone으로 옮기는 것과 실제 폐기는 다릅니다. 격리는 위치와 가용성을 바꾸지만, 실제 처분 전까지 실물이 창고에 존재한다면 SOH에 남을 수 있습니다.

## 주요 정책

1. 조정 전후 값을 모두 남기고 기존 이력을 덮어쓰지 않습니다.
2. 폐기 후보는 즉시 Unavailable로 격리합니다.
3. 승인 권한과 금액·수량 기준을 정의합니다.
4. 실사 중 입출고·이동이 발생할 때의 동결 또는 컷오프 정책을 둡니다.
5. 대량 조정과 폐기는 재시도·중복 실행을 막습니다.

## 예외 상황

- 실사 중 같은 Location에서 피킹 발생
- 1차와 2차 실사 결과 불일치
- 폐기 승인 후 실물이 정상으로 재판정됨
- 실제 처분은 했지만 시스템 반영이 실패함
- 조정으로 음수 재고가 만들어짐

## 확인 문제

1. 폐기 Zone 이동 시 바로 SOH를 줄이면 어떤 운영 사실을 잃을까요?
2. 장부 예상 수량을 보여주는 실사와 Blind Count의 차이는 무엇일까요?
3. 조정 API가 같은 요청을 두 번 받았을 때 어떤 결과가 되어야 할까요?
