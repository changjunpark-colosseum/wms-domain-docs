# 입하

<div class="page-meta"><span>입고</span><span>물량 도착</span><span>9분</span></div>

입하는 상품 낱개 수량을 확정하는 검수와 다르다. 먼저 몇 BOX·PALLET·CONTAINER가 센터에 도착했는지 확인한다.


## 입하 흐름

<div class="flow-strip"><span>입고 주문 식별</span><i>→</i><span>입고 형태 선택</span><i>→</i><span>도착 수량 입력</span><i>→</i><span>입하 Zone 스캔</span><i>→</i><span>입하 회차 완료</span></div>

::: info 현재 CGKR AS-IS — 같은 입고 묶음 처리
입고번호 하나에 WRO가 여러 개 연결된 경우, WRO 하나를 스캔해 입하를 시작하면 같은 입고에 속한 모든 WRO의 입하 작업이 함께 시작된다. 입하 Zone 스캔으로 완료할 때도 같은 묶음의 입하 작업과 일반 작업을 함께 완료 처리한다.
:::

```text
WRO 하나 스캔
→ 같은 입고의 WRO 전체 조회
→ 각 WRO의 입하 작업 생성 또는 재사용
→ 각 작업을 진행 중으로 변경
→ 입하 Zone 스캔
→ 같은 묶음의 WRO 상태를 RECV로 변경
→ 같은 묶음의 입하 작업을 완료 처리
```

따라서 현재 구현에서 WRO는 조회·표시 단위로 나뉘어 있어도 입하 시작과 완료가 항상 독립적으로 종결되는 것은 아니다.

## 입고 형태

| 형태 | 설명 |
|---|---|
| BOX | 박스 단위로 도착 |
| PALLET | 팔레트 단위로 도착 |
| CONTAINER | 컨테이너·대형 적재 단위로 도착 |

## 입고 형태·적재 형태 제한

| 조건 | 현재 CGKR 처리 |
|---|---|
| 입고 형태가 BOX | 적재 형태를 생략할 수 있음 |
| 입고 형태가 BOX가 아님 | 적재 형태 필수 |
| WRO가 1개이고 PALLET | 허용된 적재 형태 선택 |
| WRO가 여러 개이고 `PALLET + FLOOR` | 선택 차단 |

`PALLET + FLOOR + 복수 WRO` 제한은 입고 등록, 상세 변경과 모바일 입하 정보 저장 경로에 모두 존재한다. 다만 신규 화면의 필수값 판단과 백엔드 검증 조건이 완전히 같지 않아 화면별 동작 확인이 필요하다.

## 수량 관리

```text
남은 입하 수량 = 신청 수량 - 누적 입하 수량 - 종결 수량
```

## 정책

1. 입하 진행도는 SKU EA가 아니라 신청한 입고 형태 수량으로 관리한다.
2. 여러 회차로 나눠 입하할 수 있다.
3. 누적 수량과 남은 수량을 매번 다시 계산한다.
4. 입하 완료 수량을 검수 작업 대상으로 전달한다.
5. 부족·초과·회송은 입하 완료 상태와 별도 이력으로 관리한다.
6. 입하 수량이 신청 잔여를 초과하면 정상 완료하지 않는다.
7. 처리자, 시각, 입하 Zone과 수량을 기록한다.
8. 같은 입고에 연결된 여러 WRO의 입하 작업은 현재 구현에서 함께 시작·완료될 수 있다.
9. BOX가 아닌 입고 형태에는 적재 형태를 함께 지정한다.
10. 여러 WRO가 연결된 입고에는 `PALLET + FLOOR` 조합을 허용하지 않는다.

## 현재 구현상 주의점

- WRO별로 화면에 표시되는 입하 진행도와 실제 묶음 작업의 시작·완료 범위가 다를 수 있다.
- 취소되었거나 이미 입하가 끝난 입고를 스캔해도 작업을 먼저 진행 중으로 변경한 뒤 종료 응답을 반환할 가능성이 있다.
- 묶음 중 일부 WRO만 실제 도착한 경우 전체 작업을 함께 완료하는 동작이 물리 입하 결과와 어긋날 수 있다.


## 예외

- 신청 물량보다 적게 도착
- 신청 잔여보다 많은 수량 도착
- 다른 입고 주문의 물량 도착
- 입하 Zone 오스캔
- 파손된 BOX·PALLET
- 센터가 수령하지 않고 회송하는 물량
