# 입고 완료

<div class="page-meta"><span>입고</span><span>상태 종결</span><span>9분</span></div>

입고 완료는 상품별 처리 결과를 집계해 입고 전체와 연결된 WRO·입고 작업을 종결하는 단계다. 현재 CGKR에서는 이 단계가 재고를 처음 생성하는 경계가 아니다.

::: info 현재 CGKR AS-IS
도착 Location 재고는 각 적치 스캔에서 즉시 증가하고 STOW Zone 재고는 같은 수량만큼 감소한다. 마지막 완료 API는 상품 상태를 집계해 입고 전체·WRO·작업 완료 표시를 갱신하며 재고 수량을 다시 변경하지 않는다.
:::

## 현재 완료 상태 계산

백엔드는 같은 입고에 포함된 모든 유효 상품을 조회하고 `ZERO`, `STOW`, `DONE` 개수를 센다.

| 전체 상품 상태 조합 | 입고 전체 상태 | 완료일 기록 |
|---|---|---:|
| 전부 `ZERO` | `DONE` | 기록 |
| `DONE + ZERO` | `DONE` | 기록 |
| `STOW + ZERO` | `STOW` | 새로 기록하지 않음 |
| `DONE + STOW + ZERO` | `STOW` | 새로 기록하지 않음 |
| `REQR`·`PROC` 포함 | 변경 없음 | 변경 없음 |
| `EXCP` 포함 | 현재 집계 분기 없음 | 변경 없음 |

상태 조합이 완료 조건에 맞으면 입고 전체와 모든 WRO를 같은 상태로 변경하고 연결된 입고 작업을 완료 표시한다. 일반 작업의 진행 상태는 이 로직에서 직접 변경하지 않는다.

## 실제 재고 반영 흐름

<div class="flow-strip"><span>적치 Location 검증</span><i>→</i><span>도착 재고 증가</span><i>→</i><span>도착 가용수량 증가</span><i>→</i><span>STOW Zone 재고 감소</span><i>→</i><span>상품 잔여 0이면 DONE</span><i>→</i><span>전체 상태 집계</span></div>

## 수량 관계

```text
한 번의 적치 수량
= 도착 Location 재고 증가
= 도착 Location 가용수량 증가
= STOW Zone 재고 감소의 절댓값
```

## Inventory와 Stock

- AS-IS 운영 재고는 적치 스캔 단위로 도착 Location에 반영된다.
- 기존 도착 재고가 있으면 수량과 가용수량을 증가시키고, 없으면 새 Location 재고를 생성한다.
- 같은 적치 수량만큼 STOW Zone 재고를 감소시킨다.
- 마지막 입고완료 처리에서는 이 수량을 다시 증가시키지 않는다.
- 별도 Inventory 원장과 입고완료 사건의 원자적 정합성은 목표 정책으로 분리해 검증해야 한다.

## 현재 AS-IS 정책

1. 적치 수량은 스캔한 도착 Location에 즉시 반영한다.
2. 적치 시 도착 재고 증가와 STOW Zone 재고 감소를 같은 처리 안에서 수행한다.
3. 상품 잔여 수량이 0이면 해당 상품을 `DONE`으로 변경한다.
4. 전체 상품 조합이 `ZERO` 또는 `DONE + ZERO`이면 입고 전체를 `DONE`으로 변경한다.
5. `STOW` 상품이 남으면 입고 전체 상태를 `STOW`로 유지한다.
6. `REQR`·`PROC` 상품이 남으면 입고 전체 상태를 완료로 바꾸지 않는다.
7. 마지막 완료 처리에서 적치된 재고를 다시 증가시키지 않는다.

## 목표 정책·검증 필요

- 미도착·회송·예외를 포함한 주문 수량 보존식
- Inventory 원장과 Location별 재고의 원자적 정합성
- 같은 완료 요청의 멱등성 및 완료일 보존
- `EXCP`가 포함된 입고의 완료·보류 기준
- 연결된 일반 작업 상태와 입고 작업 완료 표시의 일치

## 현재 구현상 주의점

- 프론트는 `EXCP`를 처리 완료 상품으로 보지만 백엔드 전체 상태 집계에서는 세지 않는다.
- `complete` 호출은 상태 조합이 맞지 않아도 성공 응답을 반환할 수 있다.
- `STOW`로 재계산할 때 기존 완료일을 명시적으로 지우지 않는다.
- `DONE` 완료 요청을 반복하면 완료일이 다시 기록될 수 있다.
- 입고 작업 완료 표시와 일반 작업 상태가 서로 다르게 남을 수 있다.
