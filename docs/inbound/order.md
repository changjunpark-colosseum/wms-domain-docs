# 입고 주문

<div class="page-meta"><span>입고</span><span>원장</span><span>8분</span></div>

입고 주문은 어느 화주의 어떤 상품이 어느 센터로 얼마나 들어올 예정인지 정의하는 입고 원장이다. CGKR에서는 화면 직접 등록이나 엑셀 등록으로 입고 신청을 만들고, 저장된 신청이 센터 입고 주문의 기준이 된다.

## 주요 정보

- 화주사·센터
- 입고 예정일
- 상품·SKU·UOM
- 예정 수량
- 예정 LOT·유효기간
- BOX·PALLET 등 입고 형태
- 요청 코멘트·첨부파일
- 주문 상태와 등록자

## 생성 흐름

<div class="flow-strip"><span>입고 요청 작성</span><i>→</i><span>상품·수량 검증</span><i>→</i><span>입고 주문 생성</span><i>→</i><span>입고번호 발번</span><i>→</i><span>센터 작업 대상 전달</span></div>

## 입고 주문과 처리 결과

```text
입고 주문 예정 수량 100EA
├─ 정상 입고 95EA
├─ 파손 2EA
└─ 미도착 3EA
```

예정 수량 100EA를 95EA로 수정해 결과를 표현하지 않는다. 예정 100EA와 정상·예외·미도착 결과를 각각 보존한다.

## 상태

| 상태 의미 | 허용 행위 |
|---|---|
| 작성 중 | 상품·수량 수정·삭제 |
| 접수 대기 | 센터 접수·신청 취소 |
| 작업 가능 | 입하·현장 작업 시작 |
| 작업 중 | 허용된 정정만 가능 |
| HOLD | 신규 작업 진입 제한 |
| 완료 | 결과 조회, 원장 수정 제한 |
| 취소 | 현장 작업 차단, 과거 이력 보존 |

## 정책

1. 입고번호는 같은 시스템 범위에서 유일해야 한다.
2. 사용 가능한 화주·센터·SKU만 주문에 포함한다.
3. 상품별 예정 수량은 0보다 커야 한다.
4. LOT·유효기간 예정값과 실제 검수값을 구분한다.
5. 작업이 시작된 주문은 원장을 직접 수정하지 않고 정정 절차를 사용한다.
6. 단건·엑셀 등록에 같은 필수값과 중복 검증을 적용한다.
7. 취소·변경에는 요청자·사유·시각을 기록한다.
8. 입하·검수 결과가 입고 주문 원장을 덮어쓰지 않는다.

## 예외

- 미등록·비활성 SKU
- 다른 화주 상품 혼입
- 예정 수량·UOM 누락
- 중복 입고 주문
- 작업 시작 뒤 원장 변경
- 일부 행만 실패한 엑셀 등록
- 취소된 주문으로 입하 시작
