# 입고 예외

<div class="page-meta"><span>입고</span><span>예외 판정</span><span>9분</span></div>

입고 예외는 정상 진행 상태와 분리해 유형·수량·사유·판정 결과를 관리한다. 입고 주문의 예정값을 실제값으로 수정해 문제를 숨기지 않는다.

## 발생 지점

| 영역 | 예외 |
|---|---|
| 입하 | 부족·초과·회송·포장 단위 불일치 |
| 검수 | 다른 상품·파손·오염·LOT·유효기간 불일치 |
| 입고 작업 | 정보 없음·수량 차이·임시 라벨 식별 실패 |
| 적치 | 파손·분실·수량 불일치 |

Location 상태·용량·Zone 정책 위반처럼 시스템이 차단한 오류는 실제 수량 예외와 구분한다.

## 수량 차이 기준

분할되지 않은 검수 행은 실수량이 예정수량의 ±10% 범위이면 정상 진행하고, 그 범위를 벗어나면 입고 예외로 분리한다.

```text
ceil(예정수량 × 0.9) 이상
floor(예정수량 × 1.1) 이하 → 정상 진행

그 외 → 입고 예외
```

LOT·유효기간별 분할 행이 자동 정상 처리되더라도 모든 분할 행의 합과 원래 예정수량의 차이는 별도로 확인한다.

## 예외 흐름

<div class="flow-strip"><span>이상 감지</span><i>→</i><span>정상 수량과 분리</span><i>→</i><span>예외 수량 점유</span><i>→</i><span>사유·증빙</span><i>→</i><span>확정 또는 기각</span><i>→</i><span>재처리·회송·종결</span></div>

## TS·CS

CGKR에서는 일부 입고 예외를 TS·CS 라벨과 작업으로 분리한다.

| 구분 | 역할 |
|---|---|
| TS | 수량 차이 등 별도 판정이 필요한 입고 예외 단위 |
| CS | 수량 오류·상품 정보 부족·검수 이상을 확인하는 작업 |

TS·CS는 예외를 식별하고 처리하는 구현 수단이며 예외 도메인 자체와 같은 의미는 아니다.

### 현재 CGKR CS 승인 효과

::: info 현재 CGKR AS-IS
CS 승인은 예외 상태만 완료하는 작업이 아니다. 승인 수량에 따라 입고 상품의 계획 수량과 처리 상태를 다시 기록한 뒤 입고 전체 상태 계산을 자동으로 호출한다.
:::

```text
CS 승인
→ 변경 계획수량 반영
├─ 변경 계획수량 0: 상품 상태 ZERO
└─ 변경 계획수량 1 이상: 상품 상태 PROC
→ CS 상태 DONE
→ 입고 전체 상태 재계산
```

변경 계획수량이 `0`이면 해당 상품은 정상 검수 대상으로 돌아가지 않고 `ZERO`로 종결된다. 수량이 남으면 `PROC`로 돌아가 검수를 계속한다.

### ICS 바코드 사용 조건

입고 검수 화면에서 `ICS`로 시작하는 CS 바코드를 스캔할 수 있지만, CS 상태가 `DONE`이 아니면 진입이 차단된다. 승인 완료된 ICS 바코드는 연결된 원래 WRO를 찾아 입고 검수 흐름을 계속하는 별칭처럼 동작한다.

```text
ICS 바코드 스캔
→ CS 상태 확인
├─ DONE 아님: 미승인 예외로 차단
└─ DONE: 연결된 WRO 조회 → 검수 데이터 표시
```

## 상태

| 상태 | 의미 |
|---|---|
| 대기 | 판정 전, 예외 수량 점유 |
| 확정 | 정상 처리 대상에서 제외하거나 예외로 인정 |
| 기각 | 점유를 해제하고 정상 잔여로 복귀 |
| 완료 | 후속 처리와 이력 저장 완료 |

## 정책

1. 예외 이력과 정상 작업 진행 상태를 분리한다.
2. 수량이 있는 예외는 판정 전에도 잔여 수량을 점유한다.
3. 확정·기각·수량 조정에 처리자·시각·사유를 남긴다.
4. ±10% 허용 범위를 벗어난 초과·부족 수량을 정상 재고에 포함하지 않는다.
5. 부족 수량은 미도착 잔여의 종결 여부를 명시한다.
6. 예외 기각 시 해당 수량을 정상 잔여로 되돌린다.
7. 회송 수량은 정상 입고 완료 수량에서 제외한다.
8. 목표 정책에서는 미결 예외가 있으면 입고 완료를 차단한다. 현재 백엔드 전체 상태 계산은 `EXCP`를 집계하지 않으므로 실제 강제 여부를 별도 검증한다.
9. CS 승인 수량이 0이면 해당 상품을 `ZERO`로 종결한다.
10. CS 승인 수량이 남으면 해당 상품을 `PROC`로 되돌려 검수를 계속한다.
11. CS 승인 뒤 입고 전체 상태를 다시 계산한다.
12. 승인 완료되지 않은 ICS 바코드로 검수 흐름에 진입하지 않는다.

## 현재 구현상 주의점

- 프론트는 변경 계획수량과 실입고수량이 같아야 예외 승인을 진행하도록 제한한다.
- CS 승인 후 자동 완료 계산은 `EXCP` 상품을 집계하지 않아 입고 전체 상태가 갱신되지 않을 수 있다.
- 변경 수량·상품 상태·CS 완료·입고 전체 재계산이 여러 책임에 걸쳐 있어 실패 시 어느 단계까지 반영됐는지 확인이 필요하다.


## 예외

- 예외 수량 중복 점유
- 증빙 없는 파손·불량 확정
- 승인 없는 과입고 편입
- 기각 후 잔여 수량 미복구
- TS·CS 라벨 중복 발행
- 장기간 미결 예외
