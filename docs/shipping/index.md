# 배송·송장 개요

<div class="page-meta"><span>배송·송장</span><span>전체 흐름</span><span>10분</span></div>

배송·송장 도메인은 출고 화물을 택배사와 연결하고, 배송지 검증부터 송장 발번·출력·부착·추적과 반품 원송장 조회까지 송장의 생명주기를 관리한다.

## 전체 흐름

<div class="flow-strip"><span>배송지·주소 검증</span><i>→</i><span>택배사·배송 방식 선택</span><i>→</i><span>송장 발번·등록</span><i>→</i><span>출력·부착</span><i>→</i><span>패킹·상차 확인</span><i>→</i><span>배송 추적</span><i>→</i><span>반품 원송장 조회</span></div>

## 하위 기능

| 기능 | 역할 |
|---|---|
| 배송지·주소 | 주소 형식·우편번호·정제 결과 검증 |
| 택배사·배송 방식 | 계약·서비스·발번 가능 여부 선택 |
| 송장 발번 | 택배사 API로 운송번호 생성 |
| 자체·임시송장 | API 외 등록·임시 출력 처리 |
| 송장 출력 | 일반·순차 출력과 출력 이력 |
| 재출력 | 기존 송장번호 유지·재인쇄 |
| 추가 송장 | 분할 Box의 추가 운송번호 생성 |
| 택배사 변경 | 기존 송장 무효화·새 택배사 발번 |
| Box·송장 연결 | 박스별 내용물·송장 관계 보존 |
| 배송 추적·반품 | 배송 상태와 원송장 기반 반품 조회 |

## 출고 유형별 정책

| 출고 유형 | 송장 발행 | 배송 처리 |
|---|---:|---|
| B2C 일반 출고 | 가능 | 택배 송장·Box·배송 추적 사용 |
| B2B 차량 출고 | 불가 | 패킹 슬립·카톤 라벨·차량 인계 사용 |

## 공통 정책

1. B2C 송장 대상 주문에만 송장을 발행한다.
2. 송장번호, 택배사, 주문·Box와 출력 이력을 연결한다.
3. 주소 검증 실패와 송장 발번 실패를 구분한다.
4. 재출력은 기존 번호를 유지하고 재발번은 기존 번호를 무효화한다.
5. 같은 Box에 여러 유효 송장이 동시에 연결되지 않게 한다.
6. 송장 존재만으로 피킹·패킹 완료를 대신하지 않는다.
7. 반품에서 원출고 송장과 상품·수량을 조회할 수 있어야 한다.
