# 체적·중량

<div class="page-meta"><span>상품</span><span>물류 취급 정보</span><span>8분</span></div>

체적은 상품이나 포장 단위가 **공간을 얼마나 차지하는지** 나타내는 값이다. 중량이 “얼마나 무거운가”라면 체적은 “얼마나 큰 공간이 필요한가”를 설명한다.

창고에서는 수량만으로 공간을 판단할 수 없다. 같은 10EA라도 휴대전화 케이스 10개와 의자 10개가 필요한 선반·박스·차량 공간은 전혀 다르다. 그래서 WMS는 수량과 함께 가로·세로·높이, 체적과 중량을 관리한다.

## 체적이란

직육면체 형태의 상품·포장은 다음과 같이 계산한다.

```text
체적 = 가로 × 세로 × 높이
```

가로 30cm, 세로 20cm, 높이 10cm인 BOX의 체적은 다음과 같다.

```text
30cm × 20cm × 10cm
= 6,000cm³
= 0.006m³
= 6L
```

| 단위 | 의미 | 관계 |
|---|---|---|
| `cm³` | 센티미터 기준의 작은 체적 | 가로·세로·높이를 cm로 입력했을 때의 곱 |
| `m³` | 미터 기준의 체적 | `1m³ = 1,000,000cm³` |
| `CBM` | 물류에서 사용하는 세제곱미터 표현 | `1CBM = 1m³` |
| `CUFT` | 세제곱피트 | `1CUFT ≈ 28,317cm³` |

체적값만 저장하고 단위를 생략하면 같은 숫자를 서로 다르게 해석할 수 있다. 치수 단위와 체적 단위는 반드시 함께 관리한다.

## 왜 필요한가

| 사용하는 업무 | 체적으로 판단하는 내용 |
|---|---|
| Location 설계 | 선반·랙·바닥 Location에 상품이 들어가는지 |
| 적치 추천 | 남은 공간과 상품 크기를 비교해 적합한 Location을 고를 수 있는지 |
| 재고 Capacity | 수량은 적어도 부피 때문에 Location이 가득 찼는지 |
| 패킹 | 어떤 Box가 필요한지, 합포장이 가능한지, 빈 공간이 얼마나 생기는지 |
| 배송 | 차량·팔레트·택배 화물이 차지하는 공간과 용적중량을 계산할 수 있는지 |
| 작업 계획 | 한 번에 Cart·Con으로 운반할 수 있는 양과 작업 횟수를 추정할 수 있는지 |

체적이 없으면 시스템은 “수량 20개”만 알 수 있고, 실제로 작은 선반 하나면 되는지 팔레트 여러 개가 필요한지 판단할 수 없다.

## 중량과 함께 보는 이유

체적과 중량은 서로 대신할 수 없다.

| 상품 특성 | 체적 | 중량 | 운영상 주의점 |
|---|---:|---:|---|
| 솜·휴지처럼 크고 가벼움 | 큼 | 작음 | 공간과 차량 적재 면적이 먼저 부족해질 수 있음 |
| 금속 부품처럼 작고 무거움 | 작음 | 큼 | 선반 허용 하중과 작업자 안전이 먼저 문제가 될 수 있음 |

Location과 Box는 `들어가는가`뿐 아니라 `무게를 견디는가`도 함께 확인해야 한다. 체적 조건을 만족해도 최대 중량을 초과하면 적치하거나 포장할 수 없다.

## UOM별로 따로 관리한다

체적은 SKU 하나에 하나만 두기보다 실제 취급 단위별로 관리해야 한다.

```text
상품 A
├─ 1 EA   : 낱개 외형과 중량
├─ 1 PACK : 포장된 PACK 외형과 중량
├─ 1 BOX  : 출고 BOX 외형과 중량
└─ 1 PLT  : 적재 완료 팔레트 외형과 중량
```

`1 BOX = 12 EA`라고 해서 BOX 체적이 EA 체적의 정확히 12배가 되는 것은 아니다. 완충재, 칸막이, 박스 두께와 빈 공간이 포함되기 때문이다. 반대로 접히거나 포개지는 상품은 단순 합보다 실제 적재 체적이 작을 수 있다.

따라서 EA 체적으로 BOX·PLT 체적을 임의 계산하지 않고, 물류에서 실제로 이동·적치하는 포장 상태의 외곽 치수를 UOM별로 측정한다.

## WMS에서 사용하는 흐름

<div class="flow-strip"><span>상품·UOM 등록</span><i>→</i><span>치수·중량 입력</span><i>→</i><span>체적 계산</span><i>→</i><span>입고 검수에서 보완</span><i>→</i><span>적치·Capacity 판단</span><i>→</i><span>패킹·배송 계산</span></div>

| 객체·업무 | 책임 |
|---|---|
| 상품·UOM | 가로·세로·높이·체적·중량의 기준정보 소유 |
| 입고 검수 | 값이 없거나 실물과 다를 때 측정·보완 |
| Location | 허용 체적·중량과 현재 점유량 관리 |
| 적치 | 상품 UOM과 Location의 남은 Capacity 비교 |
| 패킹 | 내용물 체적을 기준으로 Box 후보와 합포장 가능성 판단 |
| 배송 | 실제 포장 치수·중량으로 운임과 차량 적재량 판단 |

입고에서 체적을 입력하더라도 입고 건마다 별도의 체적을 만드는 것은 아니다. 보완한 값은 상품·UOM 기준정보로 관리하고 이후 작업이 같은 기준을 사용한다.

## 용적중량

배송사는 실제 중량뿐 아니라 화물이 차지하는 공간을 중량으로 환산한 **용적중량**을 사용할 수 있다.

```text
용적중량 = 가로 × 세로 × 높이 ÷ 환산계수
```

환산계수와 적용 단위는 택배사·운송 방식·계약마다 다르다. WMS에서 하나의 고정값으로 단정하지 않고, 적용할 운송 계약의 기준을 사용해야 한다.

일반적으로 실제 중량과 용적중량 중 큰 값을 운임 판단에 쓰는 경우가 많다. 크지만 가벼운 화물도 차량 공간을 많이 차지하기 때문이다.

## 계산 예시

BOX 하나의 외곽 치수가 `40cm × 30cm × 25cm`라면 다음과 같다.

```text
BOX 1개 체적 = 30,000cm³ = 0.03CBM
BOX 20개 예상 체적 = 0.6CBM
```

남은 Location Capacity가 `0.5CBM`이면 수량상 여유가 있어도 체적 기준으로는 모두 적치할 수 없다. 다만 실제 적재에서는 방향, 빈 공간, 팔레트와 안전 여유가 생기므로 단순 체적 합만으로 100% 채울 수 있다고 판단하지 않는다.

## 정책

1. 체적은 가로·세로·높이와 동일한 치수 단위를 기준으로 계산한다.
2. 치수 단위, 체적 단위와 중량 단위를 값과 함께 저장한다.
3. 상품 본체가 아니라 실제 입고·적치·출고하는 포장 상태의 외곽 치수를 측정한다.
4. 가로·세로·높이·체적·중량이 `0` 이하이거나 단위가 없으면 Capacity 판단에 사용하지 않는다.
5. EA·PACK·BOX·PLT의 치수·체적·중량을 UOM별로 구분한다.
6. 체적은 치수에서 한 번만 계산하고 화면과 서버가 서로 다른 단위로 중복 계산하지 않는다.
7. 단위 변환과 소수점 반올림 기준을 모든 입고·재고·출고 업무에서 동일하게 적용한다.
8. 기준정보를 변경해도 완료된 과거 작업의 치수·운임 기록을 새 값으로 소급 변경하지 않는다.
9. Location·Box Capacity에는 적재 방향과 안전 여유를 고려하며 계산상 체적을 100% 사용할 수 있다고 가정하지 않는다.
10. 용적중량 환산계수는 택배사·운송 계약별 정책으로 관리한다.

## 예외

- 치수는 cm인데 체적을 CUFT 값으로 해석함
- 화면 표시 단위와 저장 단위가 다름
- 가로·세로·높이 중 하나가 누락되거나 `0`임
- EA 치수를 BOX·PLT에 그대로 사용함
- 상품 본체만 측정하고 실제 포장재·완충재를 제외함
- 체적은 허용되지만 Location·Box의 최대 중량을 초과함
- 기준정보보다 실제 포장 크기가 커서 적치·패킹이 불가능함
- 여러 상품 합포장 시 빈 공간과 적재 방향을 고려하지 않음
