# 바코드·UOM

<div class="page-meta"><span>상품</span><span>식별·수량 단위</span><span>12분</span></div>

바코드는 SKU를 스캔으로 찾는 식별자이고 UOM(Unit of Measure)은 수량을 표현하는 단위다. 바코드와 UOM은 재고 자체가 아니라 SKU의 취급 기준이다.

## 바코드

- 하나의 SKU가 여러 바코드를 가질 수 있다.
- 같은 테넌트 안에서 하나의 바코드가 여러 ACTIVE SKU를 가리키지 않게 한다.
- EA·INNER_BOX·BOX 등 포장 단위별 바코드를 등록할 수 있다.
- 입고 검수, 이동, 피킹과 패킹은 바코드로 SKU와 포장 단위를 확인한다.
- 바코드를 변경·폐기해도 과거 스캔 이력과 주문 참조는 보존한다.

## 상품코드 유형

CGKR의 `상품 바코드 상세`에는 실제 스캔용 바코드뿐 아니라 SKU·고객사 코드처럼 상품을 찾는 코드도 함께 저장한다. 다음 유형은 서로 다른 상품을 뜻하지 않는다. 하나의 상품 ID에 여러 유형의 코드를 연결할 수 있다.

| 유형 | 의미 | 주된 용도 |
|---|---|---|
| SKU | Stock Keeping Unit | 화주·WMS에서 재고 관리 단위를 식별하는 대표 상품코드 |
| UPC | Universal Product Code | 제조·유통 과정에서 상품을 식별하는 표준 바코드 번호 |
| CPC | 고객사 상품코드 | 고객사·화주가 자체 시스템에서 같은 상품을 식별하는 코드 |
| ETC | 기타 상품코드 | SKU·UPC·CPC로 분류하지 않는 보조 바코드나 별도 식별코드 |

```text
상품 ID 1001
├─ SKU: CGKR-SKU-001
├─ UPC: 8801234567890
├─ CPC: CLIENT-A-001
└─ ETC: LEGACY-001
```

화면에서 SKU·UPC·CPC·ETC가 각각 보이더라도 재고가 네 종류로 나뉘는 것은 아니다. 모두 같은 상품 ID를 찾기 위한 별칭이며 Inventory·Stock은 상품 ID를 기준으로 관리한다.

::: info CPC 명칭
CGKR 코드에는 `CPC`가 독립된 바코드 유형으로 정의돼 있지만 영문 전체 명칭은 정의돼 있지 않다. 이 문서에서는 현재 화면과 업무 용례에 따라 `고객사 상품코드`로 설명한다.
:::

## 대표 코드와 조회

한 상품에 여러 코드가 있으면 대표 여부로 기본 표시할 코드를 구분할 수 있다. 다만 실제 검색·스캔·엑셀 업로드에서 허용하는 유형과 삭제된 코드 처리 방식은 업무마다 다를 수 있다.

- 상품 조회 화면은 유형별 코드를 각각 표시할 수 있다.
- 스캔 업무는 입력 바코드로 연결된 상품 ID를 찾는다.
- 엑셀 출고 신청은 현재 유형을 제한하지 않고 같은 화주의 바코드 번호가 정확히 일치하는 상품을 찾는다.
- UPC나 CPC로 주문을 등록해도 주문 상세와 작업에서는 연결된 상품의 SKU가 표시될 수 있다.

엑셀 출고의 실제 허용 범위와 주의사항은 [엑셀 출고 신청](/outbound/excel-application)에서 확인한다.

## 바코드와 UOM의 차이

상품코드 유형은 `어떤 상품인가`를 식별하고, UOM은 `어떤 단위로 몇 개를 취급하는가`를 표현한다. 서로 연결해 사용할 수 있지만 같은 개념은 아니다.

```text
UPC 8801234567890 → 상품 ID 1001 식별
1 BOX             → 12 EA로 수량 환산
```

같은 상품에 SKU·UPC·CPC가 여러 개 있어도 UOM 환산 기준은 하나의 상품 기준정보에서 관리한다. 반대로 EA·BOX UOM이 여러 개라고 해서 상품 ID가 달라지지는 않는다.

## UOM

대표적인 단위는 다음과 같다.

| UOM | 의미 |
|---|---|
| EA | 낱개 기준 단위 |
| INNER_BOX | 내부 포장 단위 |
| BOX | 박스 포장 단위 |
| PLT | 팔레트 단위 |

```text
1 BOX = 12 EA
2 BOX 입고 = 24 EA
```

## 기준 단위

재고 장부는 하나의 기준 단위로 수량을 보존하고, 화면과 작업에서는 사용자가 입력한 UOM과 환산 수량을 함께 관리한다.

```text
입력 수량 × 환산계수 = 기준 단위 수량
```

## 정책

1. 입고·재고·출고·반품에서 같은 환산 기준을 사용한다.
2. 원래 입력한 수량·UOM과 환산 결과를 함께 보존한다.
3. 환산 결과는 재고 반영 전에 검증한다.
4. 포장 단위가 바뀌어도 이미 발생한 과거 수불 수량은 다시 계산하지 않는다.
5. 정수로 나누어지지 않는 포장 해체·재포장은 별도 작업 이력으로 관리한다.
6. 화면과 API에서 중복 환산하지 않는다.

## 예외

- 바코드가 여러 SKU에 중복 연결됨
- BOX 바코드를 EA로 잘못 인식함
- 입고와 출고의 환산계수가 다름
- 반품 수량을 두 번 환산함
- 포장 단위 변경 뒤 기존 재고와 신규 재고의 기준이 달라짐
