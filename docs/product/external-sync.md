# 외부 상품·동기화

<div class="page-meta"><span>상품</span><span>시스템 연동</span><span>10분</span></div>

외부 상품 수집, 내부 상품 매핑과 시스템 전달은 서로 다른 과정이다.

<div class="flow-strip"><span>외부 상품 수집</span><i>→</i><span>수집 결과 검증</span><i>→</i><span>Product·SKU 매핑</span><i>→</i><span>상품정보 저장</span><i>→</i><span>OMS·WMS 전달</span><i>→</i><span>결과 확인·재처리</span></div>

## 외부 상품

외부 쇼핑몰·ERP의 상품은 내부 Product·SKU와 독립된 식별자를 가진다.

- 외부 채널과 상품 ID를 함께 저장한다.
- 원본 상품명·옵션·바코드를 보존한다.
- 수집 상태와 내부 매핑 상태를 구분한다.
- 같은 외부 상품을 중복 수집해도 하나의 매핑 대상으로 식별한다.

## 매핑

```text
External Product
→ Product 또는 SKU 후보 검색
→ 옵션·바코드·판매 단위 확인
→ 내부 객체 연결
→ 매핑 활성화
```

자동 매핑 결과는 신뢰 조건을 충족할 때만 확정하고, 불확실한 상품은 검토 대상으로 남긴다.

## 상품정보 전달

전달 데이터에는 다음 정보가 포함될 수 있다.

- Product·SKU 코드와 상태
- 상품명·추가 상품명
- 바코드·UOM
- LOT·유효기간 관리 여부
- 상품 유형과 Bundle 구성

## 정책

1. 상품 수집과 내부 매핑을 별도 상태로 관리한다.
2. 데이터의 정본 시스템과 수정 권한을 명확히 한다.
3. 같은 메시지를 재전송해도 중복 상품을 만들지 않는다.
4. 전송 실패 사유와 마지막 성공 버전을 확인할 수 있어야 한다.
5. 재처리는 최신 저장값을 기준으로 수행한다.
6. 외부 상품 연결이 해제돼도 과거 주문·출고 이력은 유지한다.
7. 비활성 SKU로 신규 매핑하거나 신규 입출고를 생성하지 않는다.

## 예외

- 외부 옵션과 내부 SKU 옵션 불일치
- 바코드 중복
- 일부 시스템만 상품 갱신 성공
- 상품 상태 전송 순서 역전
- 삭제된 외부 상품의 기존 주문 유입
- Bundle 구성 전달 실패
