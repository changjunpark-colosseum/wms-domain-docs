# 작업 등록·사유

<div class="page-meta"><span>반품</span><span>작업 등록</span><span>9분</span></div>

반품 작업 등록은 센터에 들어온 상품을 확인해 정상·불량 수량을 입력하고, 실제 반품 상태에 맞는 사유와 증빙을 저장하는 단계다.

## 등록 흐름

<div class="flow-strip"><span>원출고·반품 확인</span><i>→</i><span>상품 스캔</span><i>→</i><span>정상·불량 수량 입력</span><i>→</i><span>사유·사진 입력</span><i>→</i><span>최종 확인</span><i>→</i><span>화주사 확인 여부 선택</span><i>→</i><span>저장</span></div>

## 사유 구분

| 항목 | 적용 범위 | 입력 형식 | 필수 여부 | 역할 |
|---|---|---|---|---|
| 클레임 확정 사유 | 반품 전체 | 표준 코드 선택 | 필수 | 반품건의 대표 확정 사유 |
| 클레임 확정 사유 (SKU) | 상품별 | 표준 코드 선택 | 선택 | 같은 반품 안에서 SKU별 사유가 다를 때 기록 |
| 관리자 사유 | 상품별 | 자유 입력, 최대 30자 | 선택 | 코드만으로 설명하기 어려운 특이사항 보충 |
| 센터 코멘트 | 반품 전체 | 자유 입력 | 선택 | 작업 전체에 공통인 센터 메모 |
| 사진·첨부파일 | 반품 전체 | 파일 첨부, 최대 10개 | 선택 | 파손·오염·구성품 상태 등 실물 증빙 |

`클레임 확정 사유`와 `관리자 사유`는 같은 값이 아니다. 클레임 확정 사유는 집계·연동에 사용할 수 있는 표준 코드이고, 관리자 사유는 작업자가 SKU별 상황을 설명하는 짧은 메모다. 관리자 사유만 입력해 필수 클레임 확정 사유를 대신할 수 없다.

## 클레임 확정 사유

반품 실물을 확인한 뒤 다음 코드 중 하나를 대표 사유로 선택한다.

| 사유 | 의미 |
|---|---|
| 택배파손 | 운송 과정에서 상품 또는 포장이 파손됨 |
| 센터파손 | 센터 작업 과정에서 파손됨 |
| 정상 | 정상 상품으로 자동 환불 승인 요청 가능 |
| 개봉 | 포장이 개봉된 상태로 회수됨 |
| 유통기한 오류 | 유통기한 정보 또는 잔여기간에 문제가 있음 |
| 상품불량 | 상품 자체의 품질·기능에 문제가 있음 |
| 케이스 파손 | 외부 케이스가 파손됨 |
| 내품 부족 | 구성품이나 내용물 일부가 부족함 |
| 전체 미입고 | 회수 대상 상품이 전혀 들어오지 않음 |
| 부분 회수 | 예정 수량 중 일부만 회수됨 |
| 타상품 반품 | 원출고와 다른 상품이 들어옴 |
| 기타 | 표준 사유로 분류하기 어려움 |

반품 전체의 대표 사유와 특정 SKU의 실제 사유가 다르면 상품 행의 `클레임 확정 사유 (SKU)`를 별도로 선택한다.

## 관리자 사유

관리자 사유는 상품 행에서 입력한다.

```text
상품 행의 관리자 사유 선택
→ 최대 30자 입력
→ 확인
→ 해당 SKU의 warehouseNote로 저장
```

다음처럼 표준 코드에 담기 어려운 사실을 기록한다.

- 외박스는 정상이나 상품 본체에 찍힘이 있음
- 구성품 3개 중 설명서 1개 누락
- 원송장 상품과 색상이 다름
- 정상 수량 2EA 중 1EA만 개봉됨

## 수량 입력

```text
상품별 반품 처리 수량
= 정상 수량 + 불량 수량
```

정상과 불량은 같은 상품 행에서 별도로 입력한다. 수량이 없는 상품 행은 완료할 수 없으며, LOT·유효기간 관리 상품은 해당 값과 UOM을 함께 확정한다.

## 화주사 확인 여부

작업 저장 시 센터는 화주사 확인을 요청할지 선택한다.

```text
확인 요청 안 함
→ WAIT
→ 센터가 상품 작업을 바로 진행

확인 요청
→ REQR
→ 화주사가 상세·사유·사진 확인
→ APRV
→ 센터가 상품 작업 진행
```

화주사 확인은 폐기 여부를 결정하는 자동 조건이 아니다. 확인을 요청하지 않아도 불량 수량은 폐기 Zone 경로로 갈 수 있고, 확인을 요청한 상품은 승인이 끝날 때까지 양품화·폐기 작업을 시작하지 않는다.

## 정책

1. 반품 전체의 클레임 확정 사유를 선택하지 않으면 작업 등록을 완료할 수 없다.
2. SKU별 클레임 확정 사유는 대표 사유와 다른 상품 상태를 구분할 때 사용한다.
3. 관리자 사유는 SKU별로 저장하며 최대 30자를 초과할 수 없다.
4. 관리자 사유와 센터 코멘트를 혼용하지 않는다. 상품 특이사항은 관리자 사유, 반품 전체 메모는 센터 코멘트에 기록한다.
5. 정상·불량 수량 중 하나 이상을 입력하지 않은 상품은 저장하지 않는다.
6. 반품 상품의 수량과 사유는 `WAIT` 상태에서만 변경한다.
7. 저장 전 확인 화면에서 상품·정상 수량·불량 수량·사유를 다시 검토한다.
8. 사진은 반품번호와 연결하고, 업로드 재시도가 반품 작업을 중복 생성하지 않게 한다.
9. 저장된 대표 사유와 SKU별 사유·관리자 사유를 반품 상세에서 다시 조회할 수 있어야 한다.
10. 화주사 확인을 요청한 반품은 승인 전 센터 후속 작업을 진행하지 않는다.
11. 반품 하나에 등록하는 첨부파일은 최대 10개다.


## 예외

- 대표 클레임 확정 사유 미선택
- 상품별 정상·불량 수량 모두 없음
- 관리자 사유 30자 초과
- 원출고와 다른 SKU·LOT·UOM 선택
- 완료된 상품의 수량·사유 변경 시도
- 사진 업로드 실패
- 첨부파일 11개 이상 등록
- `WAIT`가 아닌 반품 상품의 수량·사유 변경
- 대표 사유와 SKU별 사유가 불일치하지만 설명이 없음
