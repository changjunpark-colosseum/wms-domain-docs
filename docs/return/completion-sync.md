# 외부 동기화·완료

<div class="page-meta"><span>반품</span><span>완료·연동</span><span>9분</span></div>

반품 완료는 모든 반품 상품이 양품화·폐기·반송 중 하나의 경로로 종결된 상태다.

## 완료 조건

1. 모든 반입 상품의 검수와 품질 판정이 끝났다.
2. 양품 수량은 정상 Location 재입고가 완료됐다.
3. 불량 수량은 폐기·반송 경로로 종결됐다.
4. 보류·미처리 Container가 없다.
5. Cart·Container 수량 합과 상품별 완료 수량이 일치한다.

## 완료 흐름

<div class="flow-strip"><span>상품별 처리 결과 집계</span><i>→</i><span>수량 합 검증</span><i>→</i><span>반품 작업 완료</span><i>→</i><span>Cart 점유 해제</span><i>→</i><span>재고·환불 결과 전송</span><i>→</i><span>실패 건 재시도</span></div>

## 정책

1. 모든 상품이 종결되기 전에는 반품 전체를 완료하지 않는다.
2. 반품·작업 완료 시각과 처리자를 기록한다.
3. 양품화 수량만 외부 가용재고 증가 대상으로 전달한다.
4. 폐기 상품은 외부 가용재고를 증가시키지 않는다.
5. 외부 통지 실패가 내부 Stock·Inventory 변경을 다시 실행하지 않게 한다.
6. 반품번호·상품·처리 사건 ID로 중복 전송을 방지한다.
7. 외부 시스템별 성공·실패·재시도 결과를 따로 저장한다.
8. 내부 완료 뒤 외부 실패가 발생해도 반품 작업을 처리 중으로 되돌리지 않는다.

## 예외

- 일부 상품만 완료
- Cart·Container 미처리 수량 존재
- 외부 재고·환불 중복 반영
- 일부 채널만 전송 성공
- 반복 전송 실패
- 내부 완료와 외부 상태 불일치
