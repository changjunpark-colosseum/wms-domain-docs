# 출고 신청·주문

출고 신청은 어떤 상품을 몇 개, 누구에게, 어떤 배송 방식으로 보낼지 등록하는 출고 작업의 원장이다.

## 신청 시 재고 조회 범위

출고 신청 화면에 표시되는 가용재고와 실제 피킹 작업에 할당되는 Stock의 범위는 다르다.

| 출고 유형 | 신청 상품 조회 범위 | 의미 |
|---|---|---|
| B2C | Location 유형 제한 없이 조회된 가용재고 합계 | 신청 화면의 수량이며 실제 피킹 가능 수량을 보장하지 않음 |
| B2B | 피킹로케이션(`PICK`)·보관로케이션(`STRG`)의 가용재고 | B2B 주문 상품·수량 검증에 사용하는 범위 |

B2C 피킹지시 생성은 피킹로케이션(`PICK`)의 Stock만 할당한다. 따라서 B2C 신청 화면에서 가용재고가 충분해 보여도 재고가 보관로케이션(`STRG`)에만 있으면 피킹지시 생성 시 재고부족이 발생할 수 있다.

::: warning 조회와 실제 할당의 차이
B2C 신청 재고 조회에는 Location 유형 제한이 없지만 실제 피킹 할당은 피킹로케이션(`PICK`)으로 제한된다. 이 차이를 출고 가능 확정으로 해석하지 않으며, 피킹지시 생성 전에 피킹로케이션(`PICK`) 가용재고와 보충 필요 여부를 확인한다.
:::

## 정책

1. 출고번호는 센터 안에서 유일해야 한다.
2. 사용 가능한 화주·센터·SKU만 등록한다.
3. 주문 수량은 0보다 커야 한다.
4. B2C·B2B 유형별 필수 배송·작업 정보를 검증한다.
5. 출고 신청 수량과 실제 피킹·패킹·완료 수량을 덮어쓰지 않고 따로 보존한다.
6. 작업 생성 이후 상품·수량 변경은 기존 작업과 재고 계획을 함께 정리해야 한다.
7. 완료된 출고 주문의 상품·수량·수취 정보를 직접 수정하지 않는다.
8. 엑셀·연동 다건 등록에서 행별 오류와 전체 처리 결과를 확인할 수 있어야 한다.
9. 출고 신청 시 조회한 가용재고와 피킹지시 생성 시 할당 가능한 재고를 구분한다.
10. B2B 신청 재고는 피킹로케이션(`PICK`)·보관로케이션(`STRG`) 범위에서 계산한다.
11. B2C 신청 재고가 충분하더라도 피킹로케이션(`PICK`) 재고가 부족하면 피킹 가능으로 확정하지 않는다.

## 상태

| 상태 | 설명 |
|---|---|
| 출고대기 | 주문 생성 후 작업 미생성 |
| 작업대기 | 피킹 작업 생성·작업자 대기 |
| 작업중 | 피킹·패킹 진행 중 |
| 출고완료 | 상차·재고 차감 완료 |
| 취소 | 출고 작업 중단·재고 복구 |

## 예외

- 미사용 SKU·화주·센터
- 출고 수량 0 또는 음수
- 재고 부족
- 신청 가용재고는 충분하지만 피킹로케이션(`PICK`) 가용재고가 부족함
- 수취인·배송지 필수값 누락
- 중복 판매번호·출고번호
- 작업 중 주문 변경
- 완료 주문 취소 시도
