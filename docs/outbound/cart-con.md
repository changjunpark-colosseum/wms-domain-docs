# Cart·Con

<div class="page-meta"><span>출고</span><span>피킹 운반체</span><span>9분</span></div>

Cart와 Con은 피킹한 상품을 이동하고 여러 출고를 구분하기 위한 작업 운반체다. 재고 자체의 식별자인 SKU·Stock과는 다른 객체다.


## 객체 구분

| 객체 | 역할 |
|---|---|
| Cart | 개별·클러스터 피킹 작업 전체의 상품을 운반 |
| Con | Cart 안에서 출고 주문 또는 총량 피킹 슬립별 상품을 구분 |

## 피킹 방식별 사용

| 피킹 방식 | Cart | Con |
|---|---|---|
| 개별 피킹 | 작업당 하나 사용 | 사용하지 않음 |
| 송장번호 개별 | 작업당 하나 사용 | 사용하지 않음 |
| 클러스터 피킹 | 작업 전체에 하나 사용 | 출고 주문별로 하나씩 연결 |
| 송장번호 클러스터 | 작업 전체에 하나 사용 | 출고 주문별로 하나씩 연결 |
| 총량 피킹 | 사용하지 않거나 상위 운반용으로 사용 | 피킹 슬립별로 하나씩 연결 |
| B2B 피킹 | 사용하지 않음 | B2B 작업에서 상품 운반 단위로 연결 |

## 연결 흐름

### 개별 피킹

```text
작업 시작
→ Cart 스캔
→ Location·상품 피킹
→ Cart를 PACK Zone으로 인계
```

### 클러스터 피킹

```text
작업 시작
→ Cart 스캔
→ 출고 주문별 Con 연결
→ 상품 스캔
→ 지정 Con 스캔·투입
→ Cart·Con을 PACK Zone으로 인계
```

### 총량 피킹

```text
피킹 슬립 가져오기
→ Con 스캔·연결
→ Location·상품 총량 피킹
→ Con을 PACK Zone으로 인계
```

### B2B 피킹

```text
B2B 작업번호 스캔
→ Con 연결
→ Location·상품 피킹
→ Con을 PACK Zone으로 인계
```

## 정책

1. Cart·Con은 작업과 같은 센터에서 사용할 수 있어야 한다.
2. 이미 다른 진행 작업에 점유된 Cart·Con은 중복 연결하지 않는다.
3. 하나의 클러스터 작업에서 하나의 Con은 하나의 출고 주문에만 연결한다.
4. 총량 피킹의 Con은 하나의 피킹 슬립에 연결한다.
5. 상품 스캔 후 시스템이 안내한 Con과 실제 스캔한 Con이 일치해야 한다.
6. Con별 처리 수량 합은 해당 출고 또는 슬립의 피킹 수량과 일치해야 한다.
7. PACK Zone 인계가 끝나기 전에는 작업 운반체 연결을 임의 해제하지 않는다.
8. 작업 완료·취소 시 Cart·Con의 작업 점유를 해제한다.
9. Cart·Con 교체 시 기존 상품 수량과 새 운반체의 연결 이력을 남긴다.

## 예외

- 존재하지 않거나 사용할 수 없는 Cart·Con
- 다른 작업에 이미 연결된 운반체
- 다른 센터의 Cart·Con
- 클러스터 상품을 잘못된 Con에 투입
- Con별 수량 합과 작업 수량 불일치
- PACK Zone 인계 전에 운반체 연결 해제
- 작업 취소 후 Cart·Con 점유가 남음

## 반품 Cart와의 차이

출고 Cart·Con은 피킹 작업과 출고 주문·피킹 슬립을 구분한다. 반품 Cart·Container는 반입된 반품 상품을 품질 판정·양품화 작업으로 이동시키는 별도 관계를 가진다.
