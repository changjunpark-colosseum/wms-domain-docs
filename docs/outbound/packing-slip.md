# 패킹 슬립

<div class="page-meta"><span>출고</span><span>패킹</span><span>작업 식별</span></div>

패킹 슬립은 패킹할 출고 주문과 상품·수량을 식별하는 작업 문서다. 패킹 작업자는 슬립을 스캔해 검수 대상을 불러오고, 실제 상품을 확인해 Box와 송장 또는 카톤 라벨로 연결한다.

## 전체 흐름

<div class="flow-strip"><span>패킹 대상 수량 선택</span><i>→</i><span>슬립 큐 등록</span><i>→</i><span>슬립번호 생성</span><i>→</i><span>출력</span><i>→</i><span>슬립 스캔</span><i>→</i><span>상품 검수</span></div>

```text
피킹 완료 상품
→ 패킹 슬립
→ 상품·수량 검수
→ Box 구성
├─ B2C·B2B 택배: 송장 연결
└─ B2B 차량: 카톤 라벨·차량 인계
```

## 포함 정보

- 패킹 슬립번호·QR
- 출고번호·판매번호
- 피킹 작업·Cart·Con
- 상품명·SKU·바코드·수량
- 상품 이미지·취급주의·중량
- 화주·센터
- 수취인·배송지·연락처
- 출고요청일·배송 서비스 정보

패킹 슬립에는 패킹에 필요한 배송 정보가 표시될 수 있지만 택배 운송번호를 증명하는 송장과는 다른 문서다.

## 생성·출력

CGKR의 B2C 패킹 슬립 출력은 다음 세 단계를 구분한다.

```text
Queue
→ Generate
→ Print
```

| 단계 | 의미 |
|---|---|
| 큐 등록 | 선택한 상품·수량을 패킹 슬립 생성 대상으로 점유 |
| 슬립 생성 | 작업·출고·상품 수량으로 슬립번호 생성 |
| 출력 | 생성된 슬립을 프린터로 전달 |

한 번에 모든 수량을 패킹하거나 일부 수량만 분할해 여러 패킹 슬립으로 만들 수 있다. 누적 패킹 작업이 있으면 기존 처리량과 새 처리량을 함께 대사한다.

## 스캔

패킹 슬립을 스캔하면 출고 주문, 상품·수량, Cart·Con, 송장·중량 조건과 수취 정보를 조회한다. 스캔 성공은 패킹 작업 진입일 뿐 패킹 완료가 아니다.

## B2C·B2B

| 구분 | 패킹 슬립의 역할 |
|---|---|
| B2C | 주문·상품 검수 진입, Box·송장 패킹으로 연결 |
| B2B 택배 | 대량 상품 수량 확인과 Box·송장 연결 |
| B2B 차량 | 상품 수량 확인 후 카톤 라벨·차량 인계로 연결 |

## 재출력

재출력은 기존 패킹 슬립번호를 선택해 같은 내용을 다시 출력한다. 프린터 실패나 라벨 훼손 때문에 재출력하더라도 새 패킹 작업·새 슬립·새 송장을 만들지 않는다.

## 정책

1. 패킹 슬립을 출고 주문·피킹 결과와 연결한다.
2. 슬립 상품 수량은 패킹 가능한 잔여 수량을 초과할 수 없다.
3. 분할 슬립 수량 합과 누적 패킹 수량을 피킹 인계 수량과 대사한다.
4. 슬립 생성과 출력 성공을 별도 상태로 관리한다.
5. 출력 실패 시 재고·패킹 수량을 다시 반영하지 않는다.
6. 재출력은 기존 슬립번호를 유지한다.
7. 슬립 스캔만으로 상품 검수·Box·송장 완료를 대신하지 않는다.
8. 취소·재고부족·NG가 반영된 최신 패킹 대상을 사용한다.
9. 다른 작업자가 점유한 동일 패킹 작업의 중복 생성을 차단한다.
10. 패킹 슬립과 송장·카톤 라벨을 서로 다른 객체로 보존한다.

## 예외

- 존재하지 않는 패킹 슬립번호
- 다른 센터·출고의 슬립
- 잔여 수량보다 큰 슬립 생성
- 동일 패킹 작업 중복 점유
- 슬립 큐 등록 후 생성 실패
- 생성 성공 후 프린터 실패
- 주문 변경 전의 오래된 슬립 스캔
- 재출력 과정에서 새 슬립번호 생성
