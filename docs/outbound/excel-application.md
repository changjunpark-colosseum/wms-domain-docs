# 엑셀 출고 신청

<div class="page-meta"><span>출고</span><span>대량 주문 등록</span><span>9분</span></div>

엑셀 출고 신청은 여러 출고 상품·수취·배송 정보를 양식에 작성해 한 번에 주문으로 등록하는 기능이다. B2C와 B2B를 별도 기능으로 보지 않고 같은 신청 흐름에서 출고 유형과 그에 맞는 양식을 선택한다.

## 신청 흐름

<div class="flow-strip"><span>출고 유형 선택</span><i>→</i><span>화주사 선택</span><i>→</i><span>양식 다운로드</span><i>→</i><span>주문 행 작성</span><i>→</i><span>파일 업로드</span><i>→</i><span>검증·주문 생성</span><i>→</i><span>목록 확인</span></div>

센터 출고 주문 화면에서는 B2C 또는 B2B를 선택할 수 있다. 선택한 유형에 따라 업로드 작업과 다운로드 양식이 달라지므로 서로 다른 유형의 주문을 한 파일에 섞지 않는다.

| 선택 유형 | 업로드 유형 | 양식 메뉴 |
|---|---:|---|
| B2C | `52` | `UI-05S0102` |
| B2B | `53` | `UI-05S0103` |

센터 계정은 화주사를 선택하고 `.xlsx` 파일 한 개를 업로드한다. 셀러 계정은 로그인한 화주 정보로 처리한다.

## 주문 생성 단위

엑셀의 한 행을 출고 한 건으로 만들지 않는다. B2C와 B2B 모두 `Sales Order(SO No.)`가 같은 상품 행을 하나의 출고 주문으로 묶는다.

| 엑셀 입력 | 생성 결과 |
|---|---|
| 같은 SO에 서로 다른 상품 여러 행 | 출고 주문 1건과 상품 상세 여러 건 |
| 서로 다른 SO | SO별 출고 주문 |

```text
SO-001 / SKU-A / 10개 ─┐
SO-001 / SKU-B / 20개 ─┼→ 출고 주문 SO-001 / 상품 상세 3건
SO-001 / SKU-C / 30개 ─┘
```

::: info 한 출고의 복수 상품
한 출고 주문에 여러 상품을 등록할 수 있다. 상품 종류마다 행을 작성하고 같은 SO를 사용한다.
:::

같은 SO의 수취인, 주소, 출고요청일과 같은 주문 공통 정보는 그룹에서 선택된 대표 행의 값으로 생성된다. 현재 구현은 조회된 그룹의 첫 번째 항목을 사용하지만 행 조회 순서를 명시적으로 보장하지 않으므로, 같은 SO에 속한 모든 행의 공통 정보를 동일하게 작성한다.

## 상품코드 해석

B2C와 B2B 엑셀은 같은 상품 바코드 조회 로직을 사용한다. `출고상품코드`가 같은 화주의 바코드 번호와 정확히 일치하면 연결된 상품을 찾으며, 현재 조회 조건은 바코드 유형을 제한하지 않는다.

따라서 현재 구현에서는 다음 값이 매칭될 수 있다.

- 대표 SKU
- CPC(고객사 상품코드)
- UPC(일반 상품 바코드)
- ETC 바코드
- 삭제 표시된 바코드

매칭 후 주문 상품에는 입력한 바코드 문자열이 아니라 연결된 상품 ID가 저장된다. 따라서 UPC나 CPC를 입력해도 주문 화면에는 해당 상품의 SKU가 표시될 수 있다.

::: warning 현재 구현과 확정 정책의 차이
CPC는 현재 구현에서 출고상품코드로 사용할 수 있다. UPC·ETC·삭제 바코드도 현재 조회 조건상 매칭되지만, 이를 허용해야 한다는 업무 정책은 저장소에서 확인되지 않았다. 현재 동작을 확정된 허용 정책으로 해석하지 않는다.
:::

상품 바코드 조회는 B2C·B2B 출고뿐 아니라 입고 엑셀에서도 공유한다. 허용 유형이나 삭제 조건을 변경할 때는 한 업무만 보고 공통 조회를 바로 수정하지 않고 각 엑셀 업무의 영향을 함께 검토한다.

SKU·UPC·CPC·ETC의 의미와 UOM과의 차이는 [바코드·UOM](/product/barcode-uom)에서 확인한다.

## Bundle 상품

B2C와 B2B 엑셀 출고는 Bundle 상품을 등록할 수 있다. 업로드 단계에서 Bundle 대표상품의 상품코드를 입력하지만, 출고 주문 상세를 저장할 때는 대표상품 자체가 아니라 Bundle 관계에 등록된 구성 상품으로 전개한다.

```text
엑셀 입력: Bundle A × 2

Bundle A
├─ SKU-A-1 × 1  → 출고 상세 SKU-A-1 × 2
└─ SKU-A-2 × 3  → 출고 상세 SKU-A-2 × 6
```

구성 상품의 출고 수량은 `Bundle 주문수량 × 구성수량`으로 계산한다. 위 예시의 출고 주문 원장에는 주문 1건이 생성되고, 상품 상세에는 `SKU-A-1`과 `SKU-A-2`가 포함된다. Bundle A는 별도의 상품 상세로 중복 저장하지 않는다.

다만 Bundle 정보가 사라지는 것은 아니다. 각 구성 상품 상세에 부모 Bundle ID, Bundle 주문수량, 구성수량을 함께 보존한다. 피킹·재고 작업은 구성 상품을 기준으로 처리하고, 상품 라벨처럼 판매 구성을 표현해야 하는 기능은 부모 Bundle 정보를 사용할 수 있다.

| 구분 | 저장·검증 동작 |
|---|---|
| B2C 엑셀 | 구성 상품으로 전개한 뒤 각 구성 상품의 가용재고를 주문 생성 시 확인한다. 하나라도 부족하면 `번들 구성 상품의 재고 수량이 부족합니다.` 오류로 주문을 생성하지 않는다. |
| B2B 엑셀 | 동일하게 구성 상품으로 전개한다. 주문 생성 시에는 B2C와 같은 Bundle 구성 재고 검사를 적용하지 않으므로 피킹 작업 생성 전에 구성 상품의 가용재고를 확인한다. |

::: warning 과거 제한 메시지
코드에는 `엑셀로 신청하시려는 출고주문은 번들 상품 입력이 불가능 합니다.`라는 응답 메시지가 남아 있지만 현재 출고 엑셀 처리에서는 사용하지 않는다. Bundle 차단 로직은 제거됐으며, 현재 B2C·B2B 엑셀은 Bundle을 포함한 상품 유형을 저장 경로로 전달한다.
:::

## LOT 지정 행과 중복

LOT 지정은 현재 B2B 엑셀 양식에만 있는 규칙이다. 같은 SO의 동일 상품에 일반 할당과 LOT 지정 할당을 함께 사용할 수 없다.

```text
동일 상품 / 일반 할당만       → 가능
동일 상품 / LOT 지정 할당만   → 가능
동일 상품 / 일반 + LOT 혼합   → 불가
```

또한 B2B 엑셀은 같은 주문 안에서 `Sales Order + 상품코드 + LOT` 조합의 중복을 허용하지 않는다. LOT가 없는 동일 상품을 여러 행으로 나누지 않고 수량을 합쳐 한 행에 작성한다. 같은 상품에 서로 다른 LOT를 지정하는 경우에는 LOT별 상품 상세를 만들 수 있다.

::: info 유형별 차이
B2C 엑셀 생성 로직에는 위 LOT 혼합·중복 검증이 없다. 이 규칙을 엑셀 출고 전체의 공통 검증으로 적용하지 않는다.
:::

## 처리 결과와 주의사항

업로드 파일은 비동기 작업으로 처리된다. 완료되면 출고 목록을 다시 조회하고, 실패하면서 오류 파일이 생성된 경우에는 해당 파일을 내려받아 잘못된 행을 확인한다.

### 업로드 실패

- 화주사 또는 파일 누락
- `.xlsx`가 아닌 파일 또는 여러 파일 업로드
- 존재하지 않거나 아직 연동 대기 중인 상품코드
- B2B에서 동일 상품의 일반·LOT 지정 할당 혼합
- B2B에서 동일한 Sales Order·상품코드·LOT 중복

### 작성·정책 주의

- 같은 SO에 서로 다른 수취인·주소·출고요청일을 입력하면 대표 행이 아닌 값은 주문에 반영되지 않을 수 있음
- UPC·ETC·삭제 바코드의 허용 정책 미확정
