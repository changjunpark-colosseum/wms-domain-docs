# 패킹

<div class="page-meta"><span>출고</span><span>패킹</span><span>검수·포장</span></div>

패킹은 PACK Zone으로 인계된 피킹 상품을 주문과 다시 비교하고 배송 가능한 Box로 구성하는 작업이다.

## 전체 흐름

<div class="flow-strip"><span>패킹 대상 선택</span><i>→</i><span>패킹 슬립 생성·스캔</span><i>→</i><span>상품·수량 검수</span><i>→</i><span>Box·중량</span><i>→</i><span>송장·카톤 라벨</span><i>→</i><span>완료 또는 NG</span></div>

```text
피킹 완료 상품
→ 패킹 슬립
→ 상품·수량 검수
→ Box 구성
├─ B2C·B2B 택배: 송장 연결
└─ B2B 차량: 카톤 라벨·차량 인계
```

## 핵심 정보

- 출고번호·판매번호
- 패킹 작업자
- 피킹 작업·Cart·Con
- 피킹 인계 상품·수량
- Box와 Box별 내용물
- 무게·부자재·부가 작업
- 패킹 슬립
- 송장 또는 카톤 라벨

## 패킹 슬립

패킹 슬립은 패킹할 출고 주문과 상품·수량을 식별하는 작업 문서다. 작업자는 슬립을 스캔해 검수 대상을 불러오고 실제 상품을 Box와 송장 또는 카톤 라벨로 연결한다.

### 포함 정보

- 패킹 슬립번호·QR
- 출고번호·판매번호
- 피킹 작업·Cart·Con
- 상품명·SKU·바코드·수량
- 상품 이미지·취급주의·중량
- 화주·센터
- 수취인·배송지·연락처
- 출고요청일·배송 서비스 정보

패킹에 필요한 배송 정보가 표시될 수 있지만 택배 운송번호를 증명하는 송장과는 다른 문서다.

### 생성·출력

CGKR의 B2C 패킹 슬립 출력은 세 단계를 구분한다.

```text
Queue
→ Generate
→ Print
```

| 단계 | 의미 |
|---|---|
| 큐 등록 | 선택한 상품·수량을 패킹 슬립 생성 대상으로 점유 |
| 슬립 생성 | 작업·출고·상품 수량으로 슬립번호 생성 |
| 출력 | 생성된 슬립을 프린터로 전달 |

한 번에 모든 수량을 패킹하거나 일부 수량만 분할해 여러 패킹 슬립으로 만들 수 있다. 누적 패킹 작업이 있으면 기존 처리량과 새 처리량을 함께 대사한다.

### 스캔

패킹 슬립을 스캔하면 출고 주문, 상품·수량, Cart·Con, 송장·중량 조건과 수취 정보를 조회한다. 스캔 성공은 패킹 작업 진입일 뿐 패킹 완료가 아니다.

### 재출력

기존 패킹 슬립번호를 선택해 같은 내용을 다시 출력한다. 프린터 실패나 라벨 훼손 때문에 재출력하더라도 새 패킹 작업·새 슬립·새 송장을 만들지 않는다.

## B2C·B2B

| 구분 | 패킹 슬립과 완료 조건 |
|---|---|
| B2C | 주문·상품 검수 → Box → 송장 → 패킹 완료 |
| B2B 택배 | 대량 상품 수량 검수 → Box → 송장 |
| B2B 차량 | 수량 검수 → 부가 작업 → 카톤 라벨 → 차량 인계 |

### B2B 차량 출고

```text
Con·작업 식별
→ 패킹 슬립 출력·스캔
→ 상품 수량 입력
→ 부가 작업
→ 포장 수량·Box 종류
→ 카톤 라벨 전체·요약 출력
→ 작업자 기록
→ B2B 패킹 완료
```

B2B 차량 출고에는 택배 송장을 발행하지 않는다. 패킹 슬립과 카톤 라벨, Box·작업 수량과 차량 인계 정보를 기준으로 완료한다.

## 상태

| 상태 | 설명 |
|---|---|
| 대기 | 피킹 인계 완료·패킹 미시작 |
| 패킹 중 | 작업자가 주문을 점유해 검수·포장 중 |
| 완료 | 내용물·Box·필수 송장 또는 카톤 라벨 조건 충족 |
| NG | 불일치·파손·재작업 판단 필요 |

## 정책

1. 주문 하나에는 동시에 하나의 활성 패킹 작업만 허용한다.
2. 패킹 슬립을 출고 주문·피킹 결과와 연결한다.
3. 슬립 상품 수량은 패킹 가능한 잔여 수량을 초과할 수 없다.
4. 분할 슬립 수량 합과 누적 패킹 수량을 피킹 인계 수량과 대사한다.
5. 슬립 생성과 출력 성공을 별도 상태로 관리한다.
6. 출력 실패 시 재고·패킹 수량을 다시 반영하지 않는다.
7. 재출력은 기존 슬립번호를 유지한다.
8. 슬립 스캔만으로 상품 검수·Box·송장 완료를 대신하지 않는다.
9. Box별 상품·수량·무게와 송장 관계를 보존한다.
10. 내용물 불일치·파손은 정상 완료하지 않고 NG로 기록한다.
11. 취소·재고부족·NG가 반영된 최신 패킹 대상을 사용한다.
12. 패킹 완료는 상차·출고 완료가 아니다.

## 예외

- 존재하지 않는 패킹 슬립번호
- 다른 센터·출고의 슬립
- 잔여 수량보다 큰 슬립 생성
- 동일 패킹 작업 중복 점유
- 슬립 큐 등록 후 생성 실패
- 생성 성공 후 프린터 실패
- 주문 변경 전의 오래된 슬립 스캔
- 재출력 과정에서 새 슬립번호 생성
- 피킹 수량과 실물 불일치
- Box 중량·부피 초과
- 분할 Box 일부 송장 누락
