# 총량 피킹

<div class="page-meta"><span>출고</span><span>B2C 피킹</span><span>총량</span></div>

총량 피킹은 여러 B2C 출고 주문이 요구한 동일 SKU 수량을 주문별로 구분하지 않고 합계로 피킹한 뒤 패킹에서 주문별로 분배하는 방식이다.

```text
주문 A 2EA + 주문 B 3EA + 주문 C 1EA
→ 총량 피킹 6EA
→ 패킹에서 주문별 분배
```

## 작업 구조

여러 출고를 하나의 상위 총량 작업으로 묶고, 작업자가 수행할 수량을 피킹 슬립으로 나눈다.

```text
총량 피킹 작업
├─ 피킹 슬립 A → 작업자 A → Con A
├─ 피킹 슬립 B → 작업자 B → Con B
└─ 피킹 슬립 C → 작업자 C → Con C
```

모든 슬립의 상품·수량 합은 상위 총량 피킹 작업과 일치해야 한다.

## 피킹 슬립

피킹 슬립은 총량 피킹을 여러 작업자가 나눠 수행할 수 있도록 분할한 실행 단위다. 출력물 모양보다 슬립번호·작업자·Con·상품 수량과 상태를 가진 작업 객체라는 점이 중요하다.

### 포함 정보

- 슬립번호
- 상위 총량 피킹 작업번호
- 상품·Location·계획수량
- 작업자
- Con
- 처리 수량·남은 수량
- 작업 상태

### 슬립 실행 흐름

<div class="flow-strip"><span>슬립 생성·출력</span><i>→</i><span>작업자 할당·가져오기</span><i>→</i><span>Con 스캔</span><i>→</i><span>Location·상품 피킹</span><i>→</i><span>PACK Zone 인계</span><i>→</i><span>슬립 완료</span></div>

관리자 Web은 슬립을 생성·출력하고 작업자를 할당한다. PDA 작업자는 자신에게 할당된 슬립이나 아직 미배정된 슬립을 조회해 실행한다.

### 슬립 상태

| 상태 | 의미 | 전이 조건 |
|---|---|---|
| WAIT | 할당 가능·미시작 | 슬립 생성 |
| IN_PROGRESS | Con 연결·피킹 중 | Con 스캔·작업 시작 |
| DONE | 피킹·PACK Zone 인계 완료 | 모든 상품 처리 완료 |

## PDA 흐름

```text
할당된 슬립 또는 가져갈 슬립 선택
→ 슬립번호 확인·스캔
→ Con 스캔
→ Location 스캔
→ 상품·총량 스캔
→ PACK Zone 스캔
→ 슬립 완료
```

## 정책

1. 피킹 슬립은 B2C 총량 피킹 작업에 귀속한다.
2. 각 슬립은 현장에서 조회·출력·스캔할 수 있는 슬립번호를 가진다.
3. 한 슬립에는 한 시점에 한 작업자만 지정한다.
4. 한 Con은 같은 시점에 하나의 진행 중 슬립에만 연결한다.
5. 미배정 슬립은 작업자가 가져올 때 해당 작업자에게 원자적으로 할당한다.
6. 다른 작업자가 먼저 가져간 슬립을 중복 할당하지 않는다.
7. 슬립별 계획·처리·잔여 수량을 보존한다.
8. 모든 슬립 수량 합은 상위 총량 작업 계획수량과 일치해야 한다.
9. 일부 슬립 완료가 상위 총량 작업 전체 완료를 의미하지 않는다.
10. 모든 슬립이 DONE일 때 상위 총량 피킹 작업을 완료한다.
11. 총량 피킹 수량과 패킹의 주문별 분배 수량을 대사한다.
12. 모바일은 슬립을 생성하지 않고 조회·가져오기·실행을 담당한다.

## 피킹 슬립과 패킹 슬립

| 피킹 슬립 | 패킹 슬립 |
|---|---|
| 총량 피킹을 작업자별로 분할 | 패킹할 주문·상품·수량 식별 |
| 작업자·Con·피킹 상태 관리 | 패킹 검수·출력·스캔 관리 |
| 피킹로케이션(`PICK`) → PACK Zone | PACK Zone → Box·송장·패킹 완료 |

## 예외

- 존재하지 않는 슬립번호
- 다른 센터의 슬립
- 다른 작업자가 이미 가져간 슬립
- Con 미연결·중복 연결
- 슬립 수량 합과 상위 작업 수량 불일치
- 미완료 슬립이 남았는데 상위 작업 완료
- 취소된 출고가 포함된 미배정 슬립 노출
- 총량 피킹 후 주문별 분배 부족
- 일부 출고 취소로 계획 수량 변경
